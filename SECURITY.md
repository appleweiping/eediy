# Security policy / 安全策略

## What to report / 报告范围

Please report vulnerabilities in the site build, automation, dependency
configuration, or contribution workflow that could expose credentials, modify
published content without authorization, execute untrusted code, or disclose
private data.

请报告可能导致凭证泄露、未授权修改公开内容、执行不可信代码或泄露私有数据的
站点构建、自动化、依赖配置与贡献流程漏洞。

Course-link availability and editorial corrections are ordinary issues, not
security reports. Immediate physical hazards in published laboratory guidance
should be labelled as a safety-critical content issue without reproducing a
dangerous procedure.

课程链接可用性与普通编辑纠错不属于安全漏洞。若公开实验指南存在紧迫的物理危险，
请标记为安全关键内容问题，但不要重复危险操作步骤。

## Reporting / 报告方式

Use the repository’s private vulnerability-reporting feature when available.
Do not place exploit details, credentials, personal data, or an actively
dangerous procedure in a public issue. If the private feature is unavailable,
open a minimal public issue asking a maintainer to establish a private channel.

若仓库提供私有漏洞报告，请优先使用。不要在公开 issue 中放入利用细节、凭证、
个人数据或仍可实施的危险步骤。若私有功能不可用，只提交最小公开说明，请维护者
建立私密渠道。

Maintainers will acknowledge a valid report, assess scope, prepare a correction,
and coordinate disclosure after affected users have a practical mitigation.
Timelines depend on severity and third-party coordination; status will not be
fabricated when it is unknown.
