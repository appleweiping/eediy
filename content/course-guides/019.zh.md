## 先把 2011 年课程当成设计课，而不是安装指南

MIT 在 [6.01SC 课程首页](https://ocw.mit.edu/courses/6-01sc-introduction-to-electrical-engineering-and-computer-science-i-spring-2011/)
明确说 OCW Scholar 版本为 independent study 设计。这里的“完整”很具体：课程笔记、
lecture 与 recitation 视频、software/design lab、homework、nano-quiz 和历年考试都在；
但原课堂的人员、机器人和自动反馈并不在。按照
[Syllabus](https://ocw.mit.edu/courses/6-01sc-introduction-to-electrical-engineering-and-computer-science-i-spring-2011/pages/syllabus/)，
lecture 录于 Spring 2011，多数 software lab、design lab、additional exercise 和
homework 来自 Fall 2011。公开版也没有 Online Tutor，所以 PDF 中的 tutor 题不会自动
判分，许多 lab/homework 没有解答。这是档案的边界，不是漏下了一个下载按钮。

官方没有形式先修，并把 8.02 Electricity and Magnetism 列为 co-requisite。下面只是
EEDIY 用来安排补课顺序的自测，不是 MIT 的录取线或成绩线：试着写一个有测试的 Python
class；手算一阶差分方程前几步；为三节点电路列 KCL；用 Bayes rule 更新一个离散分布。
哪一项卡住，就先补那一项需要的最小知识，再回来试做 Unit 1 的前两节。不要用统一分数
决定“能不能学”；这四题的作用，是区分概念缺口和旧工具造成的报错。

## Unit、公开资源与无机器人做法

[Resource Index](https://ocw.mit.edu/courses/6-01sc-introduction-to-electrical-engineering-and-computer-science-i-spring-2011/pages/resource-index/)
把课程分成 4 个 unit。下面的现代做法都由 EEDIY 提议，不是 MIT 作业，也不是
`lib601` 的官方 Python 3 port。

| Unit | 官方问题与材料 | 现代电脑上先做什么 | 没有 Pioneer 时仍缺什么 |
| --- | --- | --- | --- |
| Unit 1 · Software engineering | Python object、procedure、state machine、combinator；notes、视频、software lab、题目 | 用 Python 3 重写小接口；给 primitive 与 combinator 准备固定输入序列和单元测试 | 旧 `soar`/Tutor 的交互，以及课堂中的即时追问 |
| Unit 2 · Signals and systems | difference equation、system function、feedback、机器人转向 | 对同一 steering model 同时算解析响应与数值响应，扫描 pole 和 controller gain | 轮胎打滑、执行器饱和、采样延迟等实体差异 |
| Unit 3 · Circuits | KCL、op-amp、Thevenin/Norton、superposition、追光传感头 | 列节点方程，再用低压 SPICE 模型比较等效电路与光强变化 | Circuits Maximus、真实光传感器、布线与器件偏差 |
| Unit 4 · Probability and planning | Bayes state estimation、search、地图与路径 | 在固定地图和随机种子上比较 hallway localizer、uniform-cost 与 A* | sonar mapping、机器人头/车体协调及真实运动误差 |

每个 unit 的节奏可以不同。Unit 1 适合“读接口—写小例子—做题—补测试”；Unit 2 要把
手推响应与数值曲线摆在一起；Unit 3 先画带节点名的图，再列方程；Unit 4 则必须保留
随机种子和失败场景。这样仍沿用课程的四次抽象练习，却不会把“启动古老机器人软件”
误当成学习目标。

## Unit 3 的 KCL 数值检查不能只写“误差很小”

设节点导纳方程为 \(Gv=i\)，EEDIY 建议报告无量纲残差

\[
\rho_{\mathrm{KCL}}=
\frac{\lVert Gv-i\rVert_\infty}
{\max(\lVert Gv\rVert_\infty+\lVert i\rVert_\infty,\ I_{\mathrm{floor}})}.
\]

对纯数值例题，可把 \(I_{\mathrm{floor}}=10^{-12}\,\mathrm{A}\) 写进测试，避免零激励时
分母失去意义。对 EEDIY 自建、缩放良好且
\(\kappa_\infty(G)\le 10^6\) 的 float64 回归样例，可以保守地把
\(\rho_{\mathrm{KCL}}\le 10^{-9}\) 设为编辑选定的报警线。它故意远高于 float64
机器精度 \(2.22\times10^{-16}\)，用来容纳缩放、实现和求解路径的差异；条件数在这里
只是识别病态样例、决定是否另做敏感度分析的诊断量。\(10^{-9}\) 不是由
\(\kappa\epsilon\) 推导出的 backward-residual 定理，更不是硬件精度指标。

一旦矩阵病态，或 \(G\) 与 \(i\) 来自实测元件，就分别报告无量纲残差、绝对 KCL
不平衡量（A）与条件数：残差检查方程是否被数值解满足，条件数另用于分析解对输入扰动的
forward sensitivity。实测比较的容差再纳入元件、仪器和模型不确定度，不把
\(\kappa\epsilon\) 直接塞进 residual threshold。这个判据完全是 EEDIY 的计算检查，
不是 MIT 提供的实验阈值。Unit 2 的解析—数值差、Unit 4 的定位误差也应按相同原则说明
量纲、输入范围和阈值来源。

## Python 2.6 与 Pioneer 只放进历史复现

[Software and Tools](https://ocw.mit.edu/courses/6-01sc-introduction-to-electrical-engineering-and-computer-science-i-spring-2011/pages/software-and-tools/)
要求 Python 2.6.x；官方测试 2.6.6，并认为 2.6.7 应可运行。配套包括 IDLE、
`lib601`、`soar` simulator，以及针对 GNU/Linux、Windows 7/XP 和当时 Mac OS X 的
时期特定说明。实体 design lab 使用 ActivMedia Pioneer 3-DX 与 Circuits Maximus。
同一页也说，大多数 design-lab 内容没有机器人仍能覆盖，但 sonar mapping、头/车体
协调和仿真—实体差异不能。

若研究原实现，把下载包和 Python 2.6 放进断网、隔离、可丢弃的 VM，记录操作系统、
解释器与文件校验和；不要把停止维护的解释器变成日常联网环境。改用 Python 3、当前
移动平台或其他传感器时，另写“EEDIY adaptation”，并重新定义坐标、采样周期、噪声、
执行器饱和与安全停机。Pioneer 3-DX 不是今天应购买的课程套件，公开站也没有现行替代
BOM 或价格。可选实体电路只做隔离、低压、限流实验；移动平台第一次动作前要有物理停机
方式并清空测试区。

## Online Tutor 消失后怎样检查学习结果

原课每周有 1 次 1.5 小时 lecture、1 次 1.5 小时 software lab 和 1 次 3 小时
design lab；software lab 的即时反馈、design lab 的搭档与 staff interview 都不能由
PDF 自动补回。自学时把不同材料分开使用：nano-quiz 先答再看公开解答；4 份书面
homework 与无解答的 tutor/lab 题用单元测试、量纲、极端输入和同伴讲解复查；2 次
midterm 与 final 则闭卷完成后才看解答。

[Final Exam](https://ocw.mit.edu/courses/6-01sc-introduction-to-electrical-engineering-and-computer-science-i-spring-2011/pages/final-exam/)
说明 final 覆盖全课且更偏重 Unit 4，并保存多个学期的试卷与解答。保留首次答卷，
按“概念、模型、计算、代码”标错，隔一周重做，再用 5 分钟说明同一种 abstraction
为什么会出现在 state machine、op-amp 和 probability distribution 中；这比对着答案
抄一份干净解法更接近原来的面谈。

如果还想做一次综合练习，可以在虚拟走廊中让 state-machine controller 读取带噪声的
光/距离模型，经线性控制移动，再用 Bayes 定位和 search 规划回程。每一层都要能单独
替换测试，并写出模型失效的输入。它是 EEDIY 的课后练习，不属于 MIT 6.01SC。选择这
门课的理由也正在这里：它不是现代 Python、完整电路或现代机器人课，而是一门把软件、
动态系统、电路与不确定性放进同一套设计判断中的入门课。
