## 课程定位

Cornell [ECE 5760 课程主页](https://people.ece.cornell.edu/land/courses/ece5760/)
当前主线是 Spring 2026 *Hardware Acceleration via FPGA*：DE1-SoC/Cyclone V，
Quartus 18.1。页面还保留 2020 录像、2017 handout 和更早的 DE2/Nios II 档案，但它们
属于不同代平台。学习记录应固定为 “Spring 2026 + DE1-SoC + Quartus 18.1”，引用旧材料
时另标年份。

课程适合已经会 C、可综合 Verilog、memory-mapped I/O、fixed-point 和基本并行算法的人。
它的重点是 ARM HPS 与 FPGA fabric 怎样分工；普通在线 HDL 模拟器不能替代 SDRAM、VGA、
audio 和 HPS bridge。带 valid/ready/backpressure 的同步接口若仍陌生，数字设计与
体系结构是必要基础。

## 作业与反馈

Spring 2026 的四项任务是 HPS 控制的 hardware ODE solver、
[Mandelbrot visualizer](https://vanhunteradams.com/DE1/Mandelbrot/Mandelbrot.html)、
[multiprocessor drum synthesis](https://vanhunteradams.com/DE1/Drum/Drum_synthesis.html)
和 final project。前 3 项依次训练定点状态更新、像素并行、离散波动方程与音频时序，同时
反复使用 HPS/FPGA 接口。

每项都应有 software reference、RTL testbench、Quartus timing/resource report，以及板上
测量或明确标注的 simulation-only 结果。ODE 与 Mandelbrot 要说明位宽、溢出和停止条件；
drum 要把采样率、计算节拍和输出对应起来。画面或声音只是演示，不能替代数值比较。

## 从完整示例读懂接口

Quartus 18.1 [设计示例索引](https://people.ece.cornell.edu/land/courses/ece5760/DE1_SOC/HPS_peripherials/Examples_version_18.html)
提供完整 ZIP。Mandelbrot 的 [HPS C 源码](https://people.ece.cornell.edu/land/courses/ece5760/DE1_SOC/HPS_peripherials/version_18_1_examples/Mandelbrot/mandelbrot_video_fix.c)、
audio 示例的 [MATLAB 脚本](https://people.ece.cornell.edu/land/courses/ece5760/DE1_SOC/HPS_FPGA/master_peripheral/EBAB_Audio/EBAB_and_HPS/UDP_audio_thread.m)
与 string synthesis 的 [Verilog/Quartus 工程](https://people.ece.cornell.edu/land/courses/ece5760/DE1_SOC/DSP/Audio/Synthesis/Improved_string/verilog_improved_string.zip)
可用来追 HPS process、bridge、memory 与 peripheral 的数据路径。

未修改工程和编译报告可作为基线，每次实验只改一个参数。顶层实体、目标器件、引脚、时钟、
Platform Designer 配置和寄存器地址来自同一版本，才构成可解释的工程；工程能打开仍需检查
约束，综合通过也仍需检查 timing closure。

## Final project 用性能问题立题

项目目标应可证伪，例如固定分辨率和时钟下的帧率，资源预算内的 processing-element 数，
或相对 software baseline 的加速。Proposal 写清模块图、I/O、定点方案、验证策略、资源与
带宽估计；最终解释瓶颈在计算、memory、bridge 还是 I/O。

公开网页不提供 DE1-SoC、Cornell workstation、现场签核或提交系统。没有板卡时仍可完成
reference model、仿真、综合和性能模型，但不能把它写成 HPS/板上验证。稳定运行范围、资源
余量和已知失效点应与性能曲线放在一起。只有当帧率或吞吐的变化能追到计算、memory、bridge
或 I/O 中的具体一段，画面和声音才说明这是加速器，而不只是一次演示。
