## 课程定位

MIT 6.5950/6.5951 **Secure Hardware Design, Spring 2025** 把微体系结构当作安全边界，
覆盖 cache side channel、transient execution、Rowhammer、CPU fuzzing、formal
verification 与 TEE。它适合具备约 6.004 水平体系结构基础、能调试 C/RTL 的学习者；
virtual address、cache set 和 speculative state 的区别属于必要的计算机组成基础。

课程中的攻击只能在本人所有或明确授权、与生产环境隔离的设备和数据上运行。没有合规裸机、
脆弱 DRAM 或机构监督时，Spectre、Rowhammer、ASLR 与 cache attack 应停在模型、公开
trace 和防御分析。这条边界很重要，但本课的学习目标仍是把攻击通道与可测试、可证明的防御
性质接起来。

## 实验与项目

[官方 calendar](https://shd.mit.edu/2025/calendar.html) 列出 14 讲，从 side channel、
cache 与 transient execution 进入 physical attack、HSM、Rowhammer、hardware-software
contract、CPU fuzzing、formal verification 和 TEE。阅读每个主题时，抓住资产、攻击者能力、
传播通道和防御性质四项，比只记录攻击成功率更有用。

[Labs 索引](https://shd.mit.edu/2025/labs.html) 的文字仍写 6 个 exercises，但表格列出
Lab 0–7，共 8 个：C debugging、website fingerprinting、cache、Spectre、Rowhammer、
ASLR bypass、RISC-V/RTL fuzzing 和 formal verification。公开
[starter repository](https://github.com/MATCHA-MIT/SHD-StarterCode) 提供 Lab 0–7
模板，却没有 solutions、grading scripts 或课程服务器。

可访问性差异决定自学顺序。Lab 2、3、5 依赖课程 bare-metal 主机，Lab 4 需要筛选过的
DRAM 与 HTCondor；[Lab 6 handout](https://shd.mit.edu/2025/labs/fuzz.html) 还依赖
`unicorn.csail.mit.edu` 和 PSP RTL simulation。相比之下，
[Lab 7 handout](https://shd.mit.edu/2025/labs/formal.html) 明确支持本地 Docker。
因此可完成 Lab 0、受控的 Lab 1 和 Lab 7，把其余实验用于 threat model、接口和防御性质分析。

## MIT 与 UNSW 是两条不同路线

MIT 偏 CPU cache、Spectre、Rowhammer、fuzzing 与形式化。若目标是密码实现、功耗和故障
注入，UNSW COMP6420 更直接；其 [syllabus](https://cgi.cse.unsw.edu.au/~cs6420/syllabus/)
和 [Hackster 平台说明](https://cgi.cse.unsw.edu.au/~cs6420/hackster/) 描述 iCE40 FPGA、
两颗 RP2040、高速 ADC、5 个 labs 与 CTF。研究问题和可用设备比课程名称更能决定选择。

## 一个缺陷比较两种防御

一个安全的校外项目，是在自写的小型 RISC-V/RTL 模块中植入一处有文档的算术或权限错误，
只在仿真中比较 differential fuzzing 与 formal assertion。保存触发输入、最小反例和
waveform，修复后让两套回归通过，并解释各自发现与漏掉了什么。这个自行设计的练习不冒充
MIT Lab 6，却能把 threat model、动态搜索、形式性质和修复回归放到同一个缺陷上。
