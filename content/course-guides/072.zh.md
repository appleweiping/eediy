## 课程定位与先修要求

MIT [6.231](https://ocw.mit.edu/courses/6-231-dynamic-programming-and-stochastic-control-fall-2015/) 是 Fall 2015 研究生课。[Syllabus](https://ocw.mit.edu/courses/6-231-dynamic-programming-and-stochastic-control-fall-2015/pages/syllabus/) 要求本科 probability，尤其 conditional distribution/expectation 与 Markov chain，并要求严谨论证。每周 2 次 90 分钟 lecture 和 1 次 1 小时 recitation，依次处理 finite-horizon、imperfect information、infinite horizon 与 approximate DP。

核心在于说明 state 为何概括历史、action 何时选择、randomness 何时揭示、cost 如何累计。Bayes conditioning 和 total expectation 仍靠套公式时，需要补概率。

## 作业与反馈

[Assignments](https://ocw.mit.edu/courses/6-231-dynamic-programming-and-stochastic-control-fall-2015/pages/assignments/) 是公开的主练习入口，共有 9 份 problem set，部分含 solution。每题的 decision timeline 要标出 information set、state/action/noise/transition/cost，由此得到 recursion。Finite horizon 标 terminal cost；partial observation 定义 belief state；infinite horizon 区分 discounted、average 与 stochastic shortest path 假设。

先选一个足以手算全部 state 的小模型作为参照，solution 只用于订正。错误应标为 state 不充分、conditioning、min/expectation 顺序、boundary 或 convergence 条件，而非只替换末行。随后实现 finite-horizon backward recursion、discounted value iteration、policy iteration 和 rollout，并保留 Bellman residual 与 policy changes。

## 考试与 exact small case 提供反馈

[Exams](https://ocw.mit.edu/courses/6-231-dynamic-programming-and-stochastic-control-fall-2015/pages/exams/) 有 2015 midterm 及历史卷/解答。计时完成 2015 卷，随后按错题主题回归。Exact DP 稳定后可看 [related videos](https://ocw.mit.edu/courses/6-231-dynamic-programming-and-stochastic-control-fall-2015/pages/related-video-lectures/) 的 approximate material；这些视频并非 Fall 2015 全课堂录像。

每个 approximation 分开记录 function class、sampling distribution、truncation、optimization 和 policy-evaluation error。大型 simulation 的 empirical cost 更低，仍不足以证明原模型上更优；始终保留可精确求解的小模型作为 regression oracle。

## Project 要从中期开始

官方课程将 homework 计 30%、midterm 30%、term paper/project 40%。[Projects](https://ocw.mit.edu/courses/6-231-dynamic-programming-and-stochastic-control-fall-2015/pages/projects/) 说明项目可做批判性文献研究，或应用建模加 analytic/computational study；这个页面也是核对交付边界的来源。

可选 battery scheduling、queue control 或 sensor selection。先定义 question、state/action/noise、
baseline 和 metric，再用 simulator 与 exact small case 比较 approximation 和消融。结果表同时列
模型假设、seed、raw results、均值/分位数/计算时间、constraint violation 和 failure case。
部分可观问题若把 hidden state 喂给 policy，只能把该结果标为 oracle baseline；实际 policy
使用 belief 或明确的 history feature。

项目最关键的一段是“为什么这些变量足以构成 state”：尝试构造两段剩余变量相同、最优
action 却不同的 history；一旦构造成功，Markov 假设就缺了信息。对 partial observation，再用
归一化与极端 observation 检查 belief update。这个反例往往比换更大的 approximator 更早指出
真正的建模错误。
