## Course fit and access requirements

CU Boulder Coursera [Sensors and Sensor Circuit Design](https://www.coursera.org/learn/sensors-circuit-interface) lists 5 modules, 5 assignments, and a thermistor data-collection project. Materials, assignments, and the certificate normally belong to the paid experience; a free trial or no-certificate option depends on account, region, and date. A landing-page visitor cannot claim access to quizzes, lab handouts, submissions, or feedback.

Complete 3 diagnostics before paying: derive \(V_{ADC}(R_T)\), code range, and self-heating error for a thermistor divider; use instrumentation-amplifier gain/common mode/offset/noise to judge saturation and in-band noise; and write C that converts ADC code to temperature while handling error states and LCD output. If 2 of the 3 are inaccessible, take the ID 136 theory route first.

## Use a Thermistor for Acquisition, Calibration, and Error Tracing

Module 1 covers thermistors, RTDs, and thermocouples. Module 2 uses PSoC, pins, amplifiers, MUX, DAC/ADC, and C for a 4-part thermistor lab. Module 3 moves to rotary encoders/resolvers and flow sensors. Module 4 treats amplifier nonidealities plus Johnson, 1/f, shot, and quantization noise. Module 5 closes with thermistor data collection, screenshots, and project assessment.

Debug along `temperature → resistance → divider voltage → analog front end → ADC code → C conversion → LCD → calibrated data`. Raw ADC values, reference voltage, resistor tolerance, sample time, environment, calibration residuals, and oscilloscope settings should correspond to the schematic and pin map. The LCD proves only the display interface. Calculate an expected range and saturation condition at every conversion boundary. If the first anomaly appears in raw ADC values, inspect the reference, divider, and pin routing; if raw codes are sound but temperature is wrong, inspect formulas, units, and table lookup.

## Verify the BOM, but expect an old toolchain

The official [BOM](https://www.colorado.edu/ecee/media/2412) showed updated 2025-02-03 when checked: PSoC 5LP `CY8CKIT-059`, LCD `NHD-0216BZ`, thermistor `570-1229-ND`, resistor `A105970CT-ND`, plus breadboard, wire, and oscilloscope. Part numbers identify revisions; verify the current lab handout before purchasing. When parts arrive, compare package, resistance curve, LCD logic level, and board revision; put the electrical difference of any substitute in the BOM diff.

Infineon’s [`CY8CKIT-059` page](https://www.infineon.com/evaluation-board/CY8CKIT-059) calls the board active/preferred and points to KitProg/PSoC Creator. Infineon’s current [PSoC Creator product page](https://www.infineon.com/psoccreator) still describes Creator as a Windows-based IDE that combines schematic hardware design, firmware, code generation, and debugging. Treat that host dependency as part of the experiment: put OS, Creator build, board revision, KitProg firmware, driver, LCD pin map, and instrument model on the environment page, then separately test enumeration, blink/ADC, LCD, and probe. A port to a generic MCU is migration practice; use a separate project to compare it with the original PSoC assignment.

Compatibility failures are useful for separating software from circuitry. When USB enumeration fails, separate cable, driver, KitProg firmware, and host policy. When an ADC example fails, separate pin routing, reference, clock, and code generation. Change one factor at a time and compare old value, new value, and observation, so a legacy-toolchain problem can be distinguished from a circuit problem rather than turning a lucky reboot into advice.

## Trace an odd temperature back to the wiring

Once formal material is available, use a known-voltage ADC transfer as the
divide. If it is unstable, the problem still lies in supply, wiring,
reference, or firmware; if it is stable, move on to the divider, thermistor
fit, and Module 5 collection. When repeats exceed expected uncertainty,
inspect contacts and supply—more decimal places do not improve a measurement.

After fitting, inspect whether residuals drift monotonically with temperature
and distinguish model error, self-heating, contacts, power variation, and
quantization. Separate calibration from checking data and heating from cooling
so model fit, hysteresis, and repeatability do not disappear into one average
curve. A screenshot matters only when the path from raw ADC code to displayed
value makes sense.

If a platform assignment is locked, the public route ends at that gap. An
Arduino or other MCU can support migration practice, but changes in firmware,
reference, resolution, and timing make it a different experiment rather than
an equivalent copy.

An anomalous temperature reading should lead back through raw code, wiring, firmware revision, and calibration conditions. Compare the successful interface with raw codes from a failure to see whether a change actually fixed the cause.

Hands-on work stops at isolated, current-limited, ≤5 V desktop circuits, with
power removed before rewiring and no people, medical sensors, mains, unverified
supplies, or exposed heaters attached. NPTEL [Electronic Measurement and Instrumentation](https://nptel.ac.in/courses/108105153)
(ID 136) explains loading and uncertainty; this course is distinctive when
real access shows where those errors enter the firmware–ADC–calibration chain.
