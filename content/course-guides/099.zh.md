## Bits、signals 与 packets 必须能互相解释

MIT [6.02 Fall 2012](https://ocw.mit.edu/courses/6-02-introduction-to-eecs-ii-digital-communication-systems-fall-2012/pages/syllabus/) 用 24 讲把数字通信分成三层：Lectures 1–7 的 Bits 处理压缩与纠错，8–16 的 Signals 处理噪声、BER、LTI 信道、调制和同步，17–24 的 Packets 处理共享、队列、路由与可靠传输。它适合已经学过 18.03、6.01 并能用 Python 写小模块的人。课程真正要练的是跨层解释：noise 与 ISI 怎样改变判决，错误怎样触发重传，delay 和 queue 又怎样限制 throughput。

## 作业与反馈

[Assignments](https://ocw.mit.edu/courses/6-02-introduction-to-eecs-ii-digital-communication-systems-fall-2012/pages/assignments/) 的 PS1–3 做 Huffman/LZW、linear block code 与 Viterbi；PS4–6 做 signaling、clock recovery、noise、ISI、eye 和 modulation；PS7–9 做 MAC、routing 与 sliding window。先为每个模块写一个可手算的小 fixture 和独立 oracle，再扩大仿真；离散码字、路径与事件序列应 exact，浮点比较则注明 sample rate、dtype、normalization、seed 与 tolerance。

课程还有 11 份带答案的 [Tutorials](https://ocw.mit.edu/courses/6-02-introduction-to-eecs-ii-digital-communication-systems-fall-2012/pages/tutorials/)，但 9 份 PS 没有公开官方 solution，原班另有 6 次 TA check-off interview。独立学习可把 tutorial 用于订正基础题，把 quiz 和 PS 的关键模块留作盲测，并请同伴临时修改噪声、链路代价或窗口，要求先预测方向再运行。

Bits 段至少要能把一个短 message 从 Huffman/LZW 的可逆性一路追到 block 或 convolutional code 的 syndrome/path metric。为 Viterbi decoder 保留极短 trellis、已知 received sequence 与逐步 survivor table；只比较最终 bit string，会漏掉 tie-break、metric normalization 和 termination 的实现差异。进入 Packets 后也保持这种 trace：每次 queue event、route update、ACK 与 timeout 都带时间和因果来源。

## Audiocom 的来源可信，旧环境却不稳定

PS4–6 的 [Audiocom ZIP](https://ocw.mit.edu/courses/6-02-introduction-to-eecs-ii-digital-communication-systems-fall-2012/resources/audiocom/) 是 MIT 官方分发，但其中 4 个 `.pyc` 没有公开源码，也缺少可重复构建链。原环境是 Python 2.7、wxPython 2.8、旧 NumPy/Matplotlib。若能在隔离 VM 中对固定输入生成 reference trace，可比较 Python 3 重写；若不能，只能依据公开 handout 重新实现，并明确写“行为等价性未验证”。

文件 loopback 应先于真实 speaker/microphone：固定 WAV、采样率、振幅限制和 seed，分别测试 transmitter、channel、synchronizer 与 receiver。硬件音频只是可选 adapter，不需要 RF 发射。换电脑后先用同一 WAV 区分算法与设备差异。

Signals 段的关键是判决点怎样从连续样本中出现。保存 transmit pulse、channel impulse response、matched-filter output、sampling phase 与 constellation decision；分别注入 noise、ISI 和 clock offset，每次只改一种因素。eye diagram 需要标出绘制窗口和归一化，BER 曲线则给出 bit 数与置信范围。随后把误码引起的重传开销带回 packet queue，比较更强编码、较低有效码率和较少重传之间的取舍。这样 receiver 失败时可以指向 timing、channel inversion 或 detector，也能解释物理层变化为何最终改变 delay 与 throughput。

## 用开源工具完成跨层综合

Mark Wickert 的非官方 [scikit-dsp-comm](https://github.com/mwickert/scikit-dsp-comm) 采用 BSD-2-Clause，面向信号与通信教学，含调制、同步、卷积码、滤波与示例 notebooks。MIT 6.02 没有把它发布为 starter code 或答案；它适合在完成原 PS 接口后，核对 BER、pulse shaping 与 synchronization 的现代实现。

最终练习可把消息压缩、卷积编码、含 noise/ISI/timing offset 的 baseband channel、packet 恢复和链路失效后的重路由接在一起，报告 BER、useful throughput、delay 与 overhead。每层列出输入、输出、单位与失败假设，并保留一次固定 seed 的端到端事件日志用于回归。若只能分别展示 codec、eye 和 routing，而说不清它们怎样限制下一层，就还没有完成 6.02。

6.02 真正考察的是跨层因果：多一点冗余怎样改变 airtime，timing error 怎样变成 packet loss，而 packet loss 又怎样触发 routing。
