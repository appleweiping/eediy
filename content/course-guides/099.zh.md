## Bits、Signals、Packets 必须连成一条因果链

MIT [6.02 Fall 2012 syllabus](https://ocw.mit.edu/courses/6-02-introduction-to-eecs-ii-digital-communication-systems-fall-2012/pages/syllabus/)
把数字通信分成 3 层。Bits 讨论 entropy、Huffman/LZW、linear block code、
convolutional code 与 Viterbi；Signals 讨论 Gaussian noise、BER、LTI channel、
convolution、Fourier、filter、modulation/demodulation；Packets 讨论 TDMA/Aloha/
carrier sense、queue、Little’s law、routing 与 reliable transport。它不是把信息论、
信号和网络各讲一点就结束，而是追问冗余怎样换可靠性、共享怎样换效率。

这种宽度也规定了结课时的解释方式。PS6 的 physical-channel 结果会限制可用 packet
rate，PS9 的 window efficiency 又取决于链路 delay；最终要能从 noise、ISI、clock
recovery 逐层说明它们怎样改变 throughput 与 latency。只分别汇报“codec 通过、eye
画出、routing 能跑”，还没有完成课程最重要的跨层推理。
实际解释可以从一次失败发送倒推：波形失真先改变采样判决，判决错误再改变包重传与到达
间隔，队列和往返时延最后决定窗口是否能填满链路。每层都应指出输入量、输出量和单位，
而不是把同一张误码率曲线在几个章节重复使用。

## 用自测决定先补哪一条，而不是决定能不能学

官方先修列出 18.03、6.01，并要求 Python 达到 6.00/6.01 水平。EEDIY 把它拆成 3 个
编辑诊断：概率上尝试算 conditional probability、expectation 与 Gaussian tail；信号
上尝试求一阶 LTI difference equation、做 convolution、解释 complex exponential；
编程上尝试在不改函数 contract 的情况下实现队列、数值 loop 与 unit test。这不是 MIT
设定的分数线，也没有“一项错就退课”的规则；做不出的具体动作只决定先复习 probability、
signals 或 Python 中哪一块。
自测结果最好直接变成第一周安排：概率推导卡住，就把随机变量和条件化写成手算题；卷积
卡住，就先用短序列逐项相乘求和；接口测试卡住，就先写纯函数和极小输入。补课范围因此
由真实错误决定，而不是由课程名称或自我感觉决定。

原课有 24 讲：Lectures 1–7 是 Bits，8–16 是 Signals，17–24 是 Packets，每段后有
1 次 quiz。教材 *Bits, Signals, and Packets* 共 19 章；11 份
[Tutorial 与 solution](https://ocw.mit.edu/courses/6-02-introduction-to-eecs-ii-digital-communication-systems-fall-2012/pages/tutorials/)
用于进入章末题，但章末题 solution 不公开。建议每 2–3 讲做一次“读章—手做
Tutorial—订正—做 PS”的小循环，不要先看完全部视频再集中写代码。

## PS、旧接口、Python 3 接口与 reference oracle

9 份 problem set 按 3+3+3 排列。[Assignments 总索引](https://ocw.mit.edu/courses/6-02-introduction-to-eecs-ii-digital-communication-systems-fall-2012/pages/assignments/)
逐项列出 PS1–PS9 的官方 PDF 与 supporting files；下表保持相同的清晰行名，因此每份
作业都可从该索引一跳到达。下面的 Python 3 contract、fixture 与 oracle 均是 EEDIY
为独立学习补的测试设计，不属于 MIT 发放代码；旧接口以 handout 和官方 ZIP 实际公开
的调用约定为准，不假装知道缺失模块的内部实现。

| PS | 问题 | 旧环境接口 | EEDIY Python 3 接口 | 最小 fixture | reference oracle 与比较方式 |
| --- | --- | --- | --- | --- | --- |
| PS1 | Huffman、LZW、compression | Python 2 task entry 与 `.zl` streams | `encode(input)->bits`、`decode(bits)->input`，另返回 code table | 4–8 个 symbol、手写 frequency table 与短 string | 手算 tree/table/bitstream；round-trip 与 bit count 必须 exact |
| PS2 | linear block code、syndrome | provider encoder/decoder module | pure bit-array encode/decode，并返回 syndrome | 一个小 \(G,H\)、0/1-bit error | 枚举全部 codeword 与 error；bits、syndrome exact |
| PS3 | convolutional code、Viterbi | provider trellis task | decode 返回 bits、state path 与 path-metric trace | 2–4-state trellis、短 received sequence | 手算 trellis；tie policy 先声明，path 与 metric exact |
| PS4–6 | signaling、clock recovery、noise、ISI、eye、filter、modulation | Audiocom sample-array/audio-device/GUI path | pure array transforms + WAV/file adapter；live audio 单独封装 | impulse、short waveform、fixed lag/noise seed、small WAV | 有隔离 VM reference trace 时才比较；离散字段 exact，浮点容差由 dtype、trace 与 normalization 推导 |
| PS7 | TDMA、Aloha、carrier sense | event simulator 与统计输出 | seeded event stream in，transmission/collision trace out | 手写少量 arrivals 与 fixed backoff | 手排时序；event count、collision、success exact |
| PS8 | distance-vector、link-state routing | topology/update simulator | graph + ordered update/event stream → routes/costs | 4-node graph 与 1 次 link failure | 手算 shortest path 和 update sequence；相同 cost 时先固定 tie policy |
| PS9 | reliable transport、sliding window | packet/ACK/timer callbacks | deterministic packet/ACK/loss/delay events → sender/receiver state trace | 小 window、固定 delay 与 1 次 loss | 手写状态转移；sequence/ACK/timer exact，throughput 按确定性时间轴计算 |

先用可手算的小例子，而不是一上来比较大型仿真曲线。exact 的离散结果无需“差不多”容差；
浮点结果则在 fixture 旁写单位、dtype、normalization、reference 来源和容差推导。接口
兼容不等于算法等价，最后还要保留复杂度、失败输入和 tie-breaking 的说明。
这张表的重点是 reference oracle 的独立性。若测试期望值由待测实现自己生成，测试只能
证明程序每次犯同一个错；手算码字、时序和路由路径虽然规模小，却能把实现与期望分开。
规模扩大后，再用已通过的小模块组合，并检查守恒关系、上下界和极端输入，而不是放弃
oracle 只看图形是否顺眼。

## Audiocom 的来源可查，行为却不一定可重现

PS4 让 speaker 把文件发送到 microphone；PS5 观察 step/impulse response、ISI 与 eye
diagram；PS6 处理 preamble、unknown lag、noise、channel distortion 和 concurrent
transmission。Assignments 总索引说明 Audiocom supporting ZIP 含 17 个 `.py` 与
4 个 `.pyc`；MIT OCW 的 [Audiocom ZIP 资源页](https://ocw.mit.edu/courses/6-02-introduction-to-eecs-ii-digital-communication-systems-fall-2012/resources/audiocom/)
则证明该 ZIP 的官方分发来源。两条事实不能混作“资源页列出文件数量”。文件的 MIT
分发来源并不含糊；真正缺少的是这 4 个 `.pyc` 的公开源码，以及能从源码生成同一文件
的可重复 build chain。

这一区别会改变 Python 3 改写的说法。若能在断网、隔离、可丢弃的 Python 2 VM 中运行
官方 ZIP，并为给定输入生成 reference trace，就可以在同一 fixture 上比较现代实现，
同时记录环境、文件 hash、sample rate、dtype、random seed 与 tolerance。若 VM 不能
生成 reference trace，则只能按公开作业描述重新实现，结论必须写“行为等价性未验证”
（behavioral equivalence unverified），不能称逐行 port 或等价替换。
即使拿到了 reference trace，也只能说明所选输入上的行为相符，不能推断隐藏模块的全部
实现。应另外准备边界输入、无信号、极短记录、异常采样率与确定性噪声，标出旧程序无法
运行或输出未定义的区域；这些空白比一句笼统的“兼容”更有信息。

[Software 页面](https://ocw.mit.edu/courses/6-02-introduction-to-eecs-ii-digital-communication-systems-fall-2012/pages/syllabus/software/)
列出 Python 2.7.x、wxPython 2.8 Unicode、numpy 1.5.1、matplotlib 1.0.1；Mac OS X
10.6 的说明要求当时适用的 32-bit packages。这是 Fall 2012 环境记录，不是今天的安装
教程。即使 ZIP 来源可信，停止维护的 interpreter、GUI 与 binary 仍只应放在隔离 VM，
不进入日常联网环境。

## 先通过 WAV，再打开 speaker

Python 3 版本先让 PS4–6 全部走 array/WAV/file loopback：固定 sample rate、seed、
amplitude limit 与输入文件，分别测试 transmitter、channel、synchronizer、receiver。
只有文件路径稳定后，才把现有电脑的 speaker/microphone 作为可选 adapter；官方没有
要求专用声卡，也没有给当前设备预算。

真实音频实验按以下顺序做：不用 headphones；接线、换设备或改变 routing 前先 mute；
在软件中加入 amplitude limiter/clip，并把操作系统与硬件音量从低处开始；扬声器远离
麦克风和耳朵；一旦出现 feedback 啸叫、意外大音量或削顶，立即停止播放并静音。不要为
“更真实”加 RF transmitter——它不是作业要求，还引入频谱与射频安全问题。
音频适配层还要记录实际设备名、声道映射、系统增益、采样率转换和缓冲长度。换电脑后
结果变化时，先用同一 WAV 通过文件路径定位软件差异，再打开扬声器检查声卡、房间和
反馈；否则硬件与算法变化会混在一起，无法判断误差来自哪里。

## 用 Tutorial、口试与端到端解释补回反馈

正式课的 9 份 PS 没有公开官方 solution，另有 6 次 15–20 分钟 TA check-off
interview；3 次 quiz 也没有公开 solution。独立学习可以用 11 份 Tutorial solution
核对基础题，再保持 quiz 为盲测。每完成 Bits、Signals、Packets 中的一段，请另一人用
15–20 分钟追问：LZW 何时扩张、Viterbi state 数怎样增长、eye 为什么闭合、distance
vector 怎样 count to infinity、window 为什么被 delay 限制。答不清时回到模型和最小
fixture，不靠给代码补注释掩盖。
口试也不追求背定义。提问者可以临时改一个概率、噪声强度、链路代价或窗口大小，要求
学习者先预测方向，再运行程序；预测与结果相反时，沿状态和单位寻找第一处分歧。这个
过程更接近原课 check-off 的作用，也能阻止“测试全绿但不知道为什么”的假完成。

最后可做一项 EEDIY 综合练习：压缩消息，加入 convolutional code，通过含 noise、ISI
与 timing offset 的 baseband channel，恢复 packet，再让多节点网络在 link failure
后重新路由。报告 useful throughput、BER、delay 与 overhead 随参数的变化，并沿
PS6 packet-rate → queue/load → PS9 window/delay 解释因果。它不是 MIT 6.02 新增
project，也不替代 stochastic processes、DSP 或 computer networks 专门课；它只检验
你是否真的把 Bits、Signals、Packets 连在了一起。
