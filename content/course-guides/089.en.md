## Grade the Background Exam Before Starting

MIT 6.341 is Alan Oppenheim’s Fall 2005 graduate course, not a first course in
discrete-time signals. The
[syllabus](https://ocw.mit.edu/courses/6-341-discrete-time-signal-processing-fall-2005/pages/syllabus/)
assumes fluency with LTI systems, sampling, Fourier transforms, and bilateral
z-transforms for deterministic and stochastic signals; 6.011 was the direct
prerequisite. The early background exam did not count toward the course grade,
but the staff explicitly described a score below 80% as evidence of weak
preparation.

For independent study, I would take the Fall 2005 background exam without
solutions or extra time. Use 80% to trigger a focused review, not as a
withdrawal line or a verdict on ability; the syllabus says only that a lower
score suggests significant weakness. A learner should also be able to explain
minimum phase and group delay from a pole-zero plot, state in both time and
frequency domains when downsampling aliases, and connect a random process’s
correlation function to its power spectrum. Knowing how to call `fft` and `filter` is not enough if
normalized frequency, ROC, or phase remains vague.

## What the Public Archive Does and Does Not Contain

The
[lecture-notes page](https://ocw.mit.edu/courses/6-341-discrete-time-signal-processing-fall-2005/pages/lecture-notes/)
lists 23 lecture positions. Notes are provided for Lectures 2–13 and 15–22;
the course overview, Lecture 14 guest lecture, and Lecture 23 “Caruso’s
Orchestra” have no corresponding notes. OCW provides no lecture video. The
sequence moves from phase and group delay, minimum-phase/all-pass systems,
sample-rate conversion, and noise shaping through IIR/FIR structures and
design, polyphase methods, and linear prediction, then DFT filtering, spectral
analysis, FFT and chirp transforms, STFT, and modulated filter banks.

Problems and readings refer to the second edition of Oppenheim, Schafer, and
Buck’s *Discrete-Time Signal Processing*. That book is not included in the
open archive. The notes identify each week’s technical center, but they are
not guaranteed to replace the assigned text. A used textbook and commercial
MATLAB may cost money; decide on those dependencies before reaching a problem
set whose references cannot be followed.

## Interleave Eleven Sets, Two Projects, and Three Exams

The
[assignments page](https://ocw.mit.edu/courses/6-341-discrete-time-signal-processing-fall-2005/pages/assignments/)
publishes Problem Sets 1–11 with solutions. The
[exams page](https://ocw.mit.edu/courses/6-341-discrete-time-signal-processing-fall-2005/pages/exams/)
provides background, midterm, and final exams with solutions from both Fall
2005 and Fall 2004. Reading all 23 lectures before attempting practice wastes
the dependency structure. A better order follows the original calendar:

1. Complete PS1–PS3 and the background exam to reinforce foundations in phase,
   sampling, and z-transforms.
2. Work PS4–PS7 while studying filter structures and design, and begin
   Project I.
3. Start PS8 when it is issued at Lecture 14, read the DFT material at Lecture
   15, take the 2005 midterm closed-book after Lecture 15, and finish PS8 with
   Lectures 16–17.
4. Start PS9 in the Lecture 17 spectral-analysis block, then continue to
   PS10–PS11, Project II, and the 2005 final. Reserve the 2004 papers for a
   second independent measurement.

Write the derivation and assumptions before opening each solution. The
correction record should classify an error as transform convention,
stability/causality, frequency scaling, implementation structure, or numerical
behavior. Merely replacing the final expression loses the diagnosis. Public
visitors do not receive the recitation and office-hour discussion that
supported the original class, so the error log must identify which concepts
need another attempt.

## What Project I and Project II Actually Require

The
[projects page](https://ocw.mit.edu/courses/6-341-discrete-time-signal-processing-fall-2005/pages/projects/)
contains one combined handout, two `.mat` inputs for Project I, and 52 `.wav`
files for Project II. Project I.A compares N=1 and N=50 all-pass filters to
test the claim that phase is inaudible. It asks for impulse response,
magnitude, group delay, pole-zero plots, and an explanation of what is heard.
Project I.B applies Butterworth, both Chebyshev types, elliptic,
Parks–McClellan, and Kaiser designs to noisy 44.1 kHz speech, comparing order,
multiplications per input sample, stability, group delay, and denoising
behavior.

Project II keeps the denoising problem but adds a compressor-by-4 and a
“hardware” budget of at most 17 multiplications per input sample. Its report
must calculate operation counts for direct and polyphase realizations and use
the assigned utterance’s waveform and listening result to explain the cost of
the chosen filter. Six attractive response plots do not answer that budget.

The original submission consisted of three reports: Project I.A at no more
than 5 pages, Project I.B at no more than 10 pages, and Project II at no more
than 10 pages. MATLAB code was not submitted, and no formal project solution
was released. The report therefore has to state the design choices; code alone
does not do that.

## A Migration Away from Athena Still Needs Checks

The official project supported MATLAB in MIT’s 2005 Athena environment, to
which OCW explicitly gives no access. `usound110.m`, `usound441.m`, `wavread`,
and the Athena Sun playback instructions are historical dependencies; even
Athena Linux was outside the project’s supported path. Current MATLAB users
must check replacements for retired functions and toolbox availability.
GNU Octave or Python/SciPy is an EEDIY migration, not the MIT-supported project
environment.

Before porting, record input filenames, sampling rates, and original variable
names, then map each retired MATLAB call to its replacement. Check pole radii
and second-order-section realizations for every IIR design. Check linear phase,
delay, and frequency normalization for every FIR design. Verify stopband
behavior before decimation and confirm the 11.025 kHz output rate. Record
floating-point tolerances, window defaults, and dB conventions. If modern
libraries choose a different order from old MATLAB, preserve the versions,
parameters, and discrepancy rather than selecting the most flattering result.

## The Course Directory Must Reproduce All Three Project Reports

Following the official [projects page](https://ocw.mit.edu/courses/6-341-discrete-time-signal-processing-fall-2005/pages/projects/)
report boundaries, the final directory should contain independent PS1–PS11
solutions with corrections, the background diagnostic, two timed exams, three
project reports, and the ported code. Project I.A should retain the N=1/N=50
pole-zero, magnitude, group-delay, and listening comparison. Project I.B
should list each filter’s specification, order, coefficients or SOS,
stability, and output waveform. Project II should put the decimation
stopband, polyphase arithmetic, and 17-multiply budget on the same page.
Playback should use a controlled volume; do not send an unclipped output
directly to headphones.

Python or Octave only replaces the vanished execution environment. It does
not remove Project I’s phase comparison, Project II’s operation-count limit,
or the three report-length boundaries. A Project II submission that sounds
cleaner but cannot account for multiplications per input sample has not met
the original requirement.
