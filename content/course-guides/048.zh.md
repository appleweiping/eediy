## 用院系页面定边界，再用 Fall 2024 starter 重建项目

如果已经能独立调试 C 层的数据结构，现在想弄清 C code 在 ISA、datapath、memory 和并行硬件眼里分别是什么，Berkeley **CS 61C: Great Ideas in Computer Architecture** 很合适；若指针与基础数字逻辑都陌生，这里建议先选 Nand2Tetris 或 6.004。它的[院系课程页](https://www2.eecs.berkeley.edu/Courses/CS61C/)给出了稳定边界：C 与汇编、处理器组织、存储系统、I/O、并行计算，以及相当于 CS 61A 加 CS 61B 的程序设计基础。旧学期网页已经转入需要 CalNet 的校内归档。Fall 2024 的 lab 与 Project 1–4 starter 仍由课程官方 GitHub 组织公开保存，足以重建主要编程路径；discussion、homework、录像与原 grader 则不能算作当前可匿名复现的材料。

课程不断换观察尺度：C 指针和内存布局、RISC-V 寄存器与调用约定、CPU 数据通路，再到 cache、并行优化和虚拟内存。独立调试指针、递归和基本数据结构是合适的程序设计基础；布尔逻辑、组合/时序电路和状态机完全陌生的学习者，可在 Project 3 前补数字逻辑。想继续做复杂 RTL 微架构，可在学完后转 Cornell ECE 4750。

## 实验与项目

官方 [Lab starter](https://github.com/61c-teach/fa24-lab-starter) 用来熟悉 C 调试、RISC-V 模拟器、Logisim 和并行性能工具。Lab 并不只是热身，它们把项目会用到的工具逐项铺开。

- [Project 1 starter](https://github.com/61c-teach/fa24-proj1-starter) 的 `snek` 用 C 训练动态结构、内存所有权和测试；sanitizer 报告通常比“终于不崩了”更能说明问题。
- [Project 2 starter](https://github.com/61c-teach/fa24-proj2-starter) 的 `CS61Classify` 用 RISC-V 实现矩阵运算与手写数字分类，重点是 calling convention、stride 和地址计算。
- [Project 3 starter](https://github.com/61c-teach/fa24-proj3-starter) 的 `CS61CPU` 在 Logisim 中实现处理器，ALU、register file、immediate generator 和 control 最终会汇合到 instruction trace。
- [Project 4 starter](https://github.com/61c-teach/fa24-proj4-starter) 的 `CS61kaChow` 用 OpenMP、SIMD 和访存优化 C kernel，也让 cache 课程内容第一次直接反映在运行时间上。

4 个项目的妙处在于观察尺度逐步下沉：C 对象之后是 RISC-V 指令，指令之后是 datapath 上的控制信号，访存模式又成为 cache 和并行优化的问题。理解这些接口，比任何单个项目的代码量都更重要。

## 访问与版本说明

目前匿名可访问的材料只有院系范围说明、[CS 61C 公开讲义](https://notes.cs61c.org/)和上面的 5 个 Fall 2024 官方 starter 仓库；旧学期 calendar、discussion、homework、录像、grader、课程服务器与 staff check-off 都不在公开包里。校外学习时，固定小输入、sanitizer、ISA/control-signal trace 和重复 benchmark 才是实际可用的反馈。

5 个仓库应统一使用 Fall 2024 接口，公开讲义只作为概念参考。混用不同学期的 starter 容易遇到已经改变的接口、测试和项目边界。这些材料能复现公开编程任务，却不能补回 enrollment、deadline、staff feedback 和隐藏考核。
