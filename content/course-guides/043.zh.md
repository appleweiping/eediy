## Failure mode 决定独立项目的顺序

沿官方 topics 依次练习：先做能穷举 truth table 的 combinational network，再做
switch synchronizer/debouncer，并主动注入 contact bounce，让 timing requirement 可以被
证伪；随后完成带 illegal-state recovery 测试的 FSM、逐周期核对 controller 的 arithmetic
datapath，最后接入一个小型 processor 或 bus peripheral。每项先写自己的 specification、
fixture 与预期时序，再写 RTL。

每个 block 配齐 written contract、RTL、assertion、testbench、lint 输出、synthesis
utilization、timing report 与 constraints，并挑一个真实失败定位到具体 cycle。波形截图用于
找错，assertion 与 testbench 负责判错。
在 transaction 中途触发 reset；有 handshake 时改变 back-pressure；并确认删掉 assertion
或改动 latency 后至少有一项测试会失败。

## 把 datapath、control 与 clock boundary 写成接口

集成前固定 address map、data width、clock domain、latency、byte enable、valid/ready 和 reset
semantics。算术结果与 architectural state 使用 reference model，在 transaction commit
边界同 RTL 对照。每个 CDC 分别标成 single-bit level、pulse、reset 或 multi-bit transfer；
two-flop synchronizer 只适合稳定的 single-bit level，其他 crossing 需要相应协议。

implementation checkpoint 写清 exact Vivado version、FPGA part、clock constraint、warning
policy、seed，以及从源文件生成工程的 command 或 Tcl script。若所选板卡不同于 Illinois
环境，把 voltage、pinout、clock、memory 与 peripheral 差异直接列在接口表里。
behavioral simulation 只回答功能是否正确；timing closure 与接线安全另行验证。

## 独立 SoC 项目只对应公开主题

在 VGA、audio、soft CPU 或 memory-mapped sensor 中选一个 peripheral-rich 结果。加入
counter、status register 和 embedded logic analyzer，把 failure 定位到首个错误 cycle 与
interface。没有板卡时止于 “pre-board complete” 并附 implementation report；有板卡时写下
bitstream hash、board revision、rail/I/O voltage check 与 bring-up 顺序。

这门课最值得练的不是让 VGA 或 audio “亮起来”，而是找到跨 block 的首个坏周期：到底是
latency contract、clock boundary，还是板级 I/O。最后比较 area、latency、clock rate 与
debug visibility；若提高 Fmax 反而让问题更难定位，这个取舍本身就是 SoC 集成的答案。
