## 6.004 课程材料

MIT OCW 公开了两个内容侧重不同的学期版本。[Spring 2017](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2017/) 有 21 个主题单元，从 digital abstraction、CMOS、组合与时序逻辑，走到 Beta、cache、pipeline、virtual memory、interrupt 和 concurrency；大多数单元配 annotated slides、topic videos 与 worksheet，最适合第一次学习。它的 syllabus 虽写 7 个 lab 与 final design project，公开导航却没有这些实验文件。

[Spring 2009 syllabus](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2009/pages/syllabus/) 则对应 8 个公开 lab、可选 project 和 5 次 quiz。因此可采用“2017 讲授 + 2009 实验/题目”，同时为所有笔记、代码和考试标明年份；这条组合路线不对应 MIT 的任何单一学期。

## 旧工具只在隔离环境运行

2009 [Tools](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2009/pages/tools/) 提供 JSim、BSim、TMSim 与 Beta 支持文件，同时引用旧 Sun J2SE。若当前 Java 无法运行，只在无网络、非管理员、不可写宿主目录的 VM 中使用旧 JRE，并写明课程文件 hash、OS、runtime 和启动参数。所有实验都是软件模拟，不需要购买“Beta 开发板”。

现代 Logisim、Verilog 或 RISC-V 可以用于迁移，原 lab 则仍以 JSim/BSim 的行为为准。保存一份原始输入的 JSim/BSim 结果，再用相同测试向量对照现代实现；这样才能区分工具差异与设计错误。

社区维护的 [compstruct-vscode](https://github.com/jamestiotio/compstruct-vscode)
采用 MIT license，为 `.jsim`、`.tmsim` 和 `.bsim` 提供语法支持及 JSim/BSim 启动入口。
它的定位是 editor extension，MIT 工具发行版与 lab 解答均不在仓库范围内；适合减少编辑器摩擦，但重跑实验仍离不开原始
JAR、命令行和输入文件。用同一份输入分别从扩展入口与命令行启动，输出不一致时先排查工作目录、classpath 和 runtime。

## 实验与项目

[2009 Labs](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2009/pages/labs/) 的 Labs 1–3 做 CMOS、adder 与 ALU；Labs 4–6 进入 Turing machine、assembly 与 Beta；Labs 7–8 完成 trap handler 与 Tiny OS。每项都把 truth table 或 instruction trace、时序假设与官方测试放在一起比较，再故意注入一个失败，说明修订前后的状态差异。到了 Beta，至少测试 reset、branch 两路、load/store 边界、interrupt 与非法指令；一张“程序运行”截图解释不了这些架构状态。

从 ALU 到 Tiny OS 始终维护一张 machine contract：每条 instruction 读写哪些寄存器与 memory，PC 在正常、branch、trap 情形怎样更新，combinational path 与 register boundary 在哪里。对一小段程序同时保存 assembly、编码后的 word、逐周期 PC/register trace 与预期 memory state。加入 interrupt 后，用同一段程序验证保存/恢复与返回点；若 architectural state 对不上，从 instruction semantics 和 timing 开始定位，再看上层程序。

cache、pipeline 与 virtual memory 虽然来自 2017 讲授，也要接到这张 contract。对一次 miss、stall 或 exception，写出软件可见状态是否改变、哪个周期允许提交，以及错误请求会不会被重放。这样现代 HDL 移植才有明确的 bit-level oracle，而不会因波形看起来“像处理器”就放过架构差异。

想在现代 HDL 里做一道比完整 Beta 小得多的状态题，可以看[同步 FIFO 小练习（非 MIT 官方实验）](https://github.com/appleweiping/eediy/tree/main/examples/sync-fifo)：满、空、回绕和 backpressure 很快就会暴露 interface contract 写得是否含糊。它不能代替 JSim、BSim 或 Beta，只把上文的状态约定缩成一个可运行的 HDL 例子。

原课还有 staff interview 与现场 checkoff，校外无法复现。可为每个 lab 录一段不看代码的口头说明，解释接口、关键状态、最坏时序与一个失败测试；这比增加漂亮截图更接近原来的现场追问。

## 题目负责拆穿“模拟器跑通”

[Tutorial Problems](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2009/pages/tutorial-problems/) 按 5 次 quiz 分组并有解答。[Exams](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2009/pages/exams/) 只有 Quiz 1、2、3、5 的题面与答案；Quiz 4 仅有答案，不能据此编造完整五考平均。先独立完成 tutorial，再限时做题面完整的历史卷。

一套能从冷启动重建的 Beta 实现最能代表课程所得：环境版本、8 个 lab、测试向量、trace、故障日志和 4 份可评分 quiz 要能互相解释。若再移植一个 ALU 或未流水 Beta 子模块到现代 HDL，应逐位比较同一向量，并明确它是迁移练习而非 MIT 官方新作业。
