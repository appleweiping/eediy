## 不要把两个 6.004 揉成一门“完整版”

MIT OCW 同时保留 Spring 2017 与 Spring 2009。2017
[课程主页](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2017/)
最适合讲授：21 个主题单元从 information/digital abstraction、CMOS、组合与时序逻辑，
一路推进到 Beta、cache、pipeline、virtual memory、interrupt、concurrency 和 parallel
processing；大多数单元带 annotated slides、topic videos 与 worksheet。可是
[2017 syllabus](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2017/pages/syllabus/)
虽写七个 lab 加期末 design project，公开导航没有对应 lab/checkoff 文件；它还写四次
闭卷 quiz、无 final。

2009 则是可执行的实验归档。[2009 syllabus](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2009/pages/syllabus/)
写八个 lab、可选 design project、五次 quiz、无 final，并使用 Athena/JSim/BSim。
因此本页采用“2017 讲授 + 2009 实验/题目”的编辑组合，不把两年的 lab 数量、评分或考试
伪装成同一学期。笔记、代码和成绩表都必须带年份。

## 旧 JRE 只能放在隔离环境里运行

2009 [Tools](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2009/pages/tools/)
公开 `jsim.jar`、`bsim.jar`、`tmsim.jar`、Beta macro/include 与各 lab checkoff 文件；
官方说明仍引用 Sun J2SE、旧版 Windows/OS X 与 `-Xms8m -Xmx32m` 参数。文件公开不等于
在 2026 的 Java runtime 上必然兼容。若必须使用旧 JRE，就放进专用虚拟机：禁用虚拟
网卡，以非管理员账户运行，不挂载任何可写的 host 目录或共享剪贴板。下载课程文件、
核对 hash 后再断网；输出需要带出时，先关机，再通过临时导出镜像转移，不让旧 Java
进程直接写宿主工作区。

环境的第一次运行只做 JSim smoke test：载入 tools 页给出的 nominal device model，
确认能打开、计算并保存一个最小结果，同时记录 OS、JRE、启动参数与文件 hash。等路线
走到 Turing machine 和 Beta 时，再分别启动 TMSim 与 BSim；不必提前制造三个与课程
进度无关的小任务。若 GUI 只能在旧 JRE 工作，就固定该 VM，不在学习
中途升级。

用 Logisim、Verilog 或现代 RISC-V 替代当然可以，但那是移植项目，不是原 lab 的直接
完成。想保留原实验语义，先让 JSim/BSim 原始输入得到可保存的输出，再做现代 HDL 端口
对照。所有实验均为软件模拟，无需 FPGA、面包板或市电；成本主要是存储与运行环境，
不存在采购“Beta 开发板”这件事。

## 用 Unit 1 worksheet 接上第一个 JSim 电路

先下载 2017 Unit 1 的 annotated slides 与 worksheet。worksheet 不看答案完成第一遍，
然后在隔离 VM 中做上面的 JSim nominal-model smoke test。前者会暴露 binary
representation、digital abstraction 或 static discipline 的缺口；后者只回答旧工具
能否运行。概念题卡住就回看相应 topic video，JSim 卡住则只查 runtime、路径与启动
参数，不要把两类问题混成“我不适合学体系结构”。

接下来按 2017 单元的知识顺序，把 2009 八个实验插到真正用得上的位置：

1. **Units 1–8 + Labs 1–3：**CMOS、Adder、ALU。每个电路留下 truth table、时序假设、
   JSim netlist、checkoff 输出与一条故意注入的错误；传播延迟和 static discipline
   要能从电路解释，不只从 worksheet 抄答案。
2. **Units 9–13 + Labs 4–6：**Turing machine、Assembly、Beta。TMSim 的转移表先证明
   状态机语义，再在 BSim 中用自写指令序列测试 arithmetic、branch、load/store 与
   illegal opcode，并从 trace 解释 PC、register file 和 control ROM。
3. **Units 14–21 + Labs 7–8：**Trap handler 与 Tiny OS。cache、pipeline、virtual
   memory、interrupt 和 concurrency 都回到同一台 Beta 上讨论；完成后再决定是否做
   2009 optional project。

[2009 Labs](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2009/pages/labs/)
确实按上述八项公开 PDF、JSim/BSim 文档和 Beta references；但原课还有 staff interview、
在线问题与 checkoff 服务，校外读者得不到这些反馈。用录屏口试替代：每项在不看代码时
解释接口、关键状态、最坏时序和一个失败测试。

## 题目与考试负责拆穿“模拟器跑通”

[Tutorial Problems](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2009/pages/tutorial-problems/)
按五次 quiz 分组，覆盖 digital abstraction、CMOS、FSM/metastability、pipeline、
machine language、Beta、cache/VM、interrupt、semaphore 与 pipelined Beta，并提供解答。
每学完一段，先做对应 tutorial，保存未订正的初稿，再在限定时间内做历史 quiz。

[2009 Exams](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2009/pages/exams/)
有 Quiz 1、2、3、5 的题面与解答，Quiz 4 只公开解答而缺题面。这一缺口必须写进记录：
前四份可计时评分，Quiz 4 solution 只能用来反向列知识点，不能编造一份“完整五考平均”。
2017 worksheet 可作为更新后的概念练习，但不能冒充 2017 正式 quiz。

## Beta 要靠指令轨迹说明，而不是一张运行截图

结课仓库至少包含版本对照表与固定工具环境、21 单元的概念图、八个 lab 的原始/修订
netlist 和 assembly、测试向量、checkoff 输出、关键波形与故障日志，以及四份可评分
历史 quiz 的初稿和错题索引。Beta 不能只写“能运行程序”：给定一组短程序，应逐条
比对参考 instruction trace，在 reset、branch taken/not-taken、memory boundary、
interrupt 与非法指令边界给出预期和实测；trap handler 和 Tiny OS 也要保留从冷启动
复现的命令与终端输出。

还可以做一个编辑建议的现代对照，而非 MIT 官方作业：把 ALU 或未流水 Beta 的一个子模块
移植到 Verilog/SystemVerilog，用同一测试向量逐位比较 JSim 与 RTL；报告说明抽象层次、
未知值、组合环路和时序模型为何不同。这样既保留历史课程的可核验证据，也能把技能迁移
到现代工具，而不是悄悄换工具后丢掉原题语义。

## 编辑选择的取舍

若只看一套材料，我会优先 2017，因为讲解颗粒度、视频与 worksheet 的配合更适合首次
学习；若要真正做出“从门到计算机”的东西，必须另开 2009 实验轨。该组合比单纯列两个
OCW 链接更有用，但它从来不是 MIT 某一学期的原样课程。

先修口径也随年份不同：2017 页面列 8.02 并在文字中假定基本编程和电学；2009 更明确
提到 C/6.001、6.002 与 Athena。校外路线不需要 Athena 账号，却要自己承担旧工具兼容、
缺失 checkoff 和 Quiz 4 题面的代价。最终 README 应用一句话写清：
“theory from Spring 2017; labs, tools, tutorials, and exams from Spring 2009。”
没有这句版本声明，再完整的 Beta 也无法让别人判断你究竟完成了什么。
