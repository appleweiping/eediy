## 访问与版本说明

Cornell ECE 2300 的官方 [Course Page](https://ocw.ece.cornell.edu/courses/ece-2300-digital-logic-and-computer-organization/)
对应 Spring 2016。校园课从 transistor switch、Boolean/combinational logic、FSM 与 timing
走到 datapath、pipeline、memory hierarchy，并有 6 个 labs、2 次 prelim 和 final；但页面
明确说 homework、labs、projects 与 exams 不公开。它适合已有练习或并行实验课、想补 Cornell
讲授脉络的人；单独使用只能读到讲授顺序，缺少完整练习与实验反馈。

## 课程结构

[Lectures and Handouts](https://ocw.ece.cornell.edu/ece-2300-lectures-and-handouts/)
公开 28 讲，从 [Lecture 1](https://ocw.ece.cornell.edu/files/2017/08/ECE2300_Lecture01-1pnhtjg.pdf)
到 [Lecture 28](https://ocw.ece.cornell.edu/files/2017/08/ECE2300_Lecture28-27bycm7.pdf)。
一本笔记放 truth table、minimization、timing/state 与 HDL；另一本放 ISA、datapath/control、
pipeline、memory address 与 performance。每学 processor，都回指 mux、register、FSM 和
timing constraint，让体系结构扎根于具体逻辑。

每讲后关掉 PDF，从空白重画关键 circuit/state/timing diagram，再写 interface 和一个
corner case。配套练习可以自己做 combinational block、counter/FSM、小型 datapath 与
direct-mapped cache，并明确标为独立练习。

## 实验与项目

让 combinational block 进入 sequential subsystem，再让 register/FSM 进入 datapath，
最后接 memory model；固定 lint、simulation、synthesis 和 regression 命令。功能仿真之外，
还要检查 setup/hold、critical path 与 constraints。最终主动改变一条 instruction、reset
polarity 或 cache line size，列出受影响的 interface/state/tests 再改 RTL。能承受这种规格
变化，才比抄完 28 份 slides 更接近真正的设计能力。

功能正确与 timing closure 要分别评价：simulation 通过只说明状态转移符合预期，synthesis
报告才回答组合路径与时钟约束。为关键寄存器记录 launch/capture、setup/hold 假设和最慢
path；若更换 memory latency，更新 interface contract 和 assertions 后再动 RTL。

架构比较使用同一 workload，同时看 CPI、clock period、stall source 与 total time。加深
pipeline 可能提高频率，也可能增加 hazard penalty；只有总时间与资源一起改善，才能称为
有效优化。出现 unconstrained path、inferred latch 或 ignored constraint 时必须回到 RTL
或约束文件；一个更高的 Fmax 若建立在未约束路径上，反而说明这次比较没有意义。
