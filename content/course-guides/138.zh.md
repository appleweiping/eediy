## 课程定位与访问条件

CU Boulder Coursera [Sensors and Sensor Circuit Design](https://www.coursera.org/learn/sensors-circuit-interface) 列 5 个 module、5 个 assignment，终点是 thermistor data-collection project。materials、assignments 与 certificate 通常属于付费体验；free trial 或 no-certificate option 是否存在取决于账号、地区和时间。只看 landing page，不能声称访问了 quiz、lab handout、submission 或 feedback。

付款前做 3 项诊断：推导 thermistor divider 的 \(V_{ADC}(R_T)\)、code range 与 self-heating error；由 instrumentation-amplifier gain/common-mode/offset/noise 判断 saturation 和 in-band noise；用 C 把 ADC code 转为 temperature，并处理 error state 与 LCD output。若 3 项中有 2 项不会，先学 ID 136 的理论。

## 用 thermistor 完成采集、标定与误差追踪

官方课程页列出的 Module 1 是 thermistor、RTD、thermocouple；Module 2 用 PSoC、pin、amplifier、MUX、DAC/ADC 与 C 完成 4-part thermistor lab；Module 3 转到 rotary encoder/resolver 与 flow sensor；Module 4 讲 amplifier nonideality、Johnson/1/f/shot/quantization noise；Module 5 做 thermistor data collection、screenshot 与 project assessment。

调试沿 `温度（temperature）→ 电阻 → 分压电压 → 模拟前端 → ADC 码 → C 语言换算 → 液晶显示 → 校准数据` 逐层展开。原始 ADC 码、参考电压、电阻容差、采样时间、环境条件、校准残差与示波器设置要能对应到原理图和引脚映射；液晶屏只证明显示接口。每个转换节点同时算预期范围与饱和条件；若异常最早出现在原始 ADC 码，先查基准电压、分压器和引脚路由，若码值正常而温度错误，再查公式、单位与查表实现。

## BOM 可核，toolchain 不新

官方 [BOM](https://www.colorado.edu/ecee/media/2412) 在查阅时标为 updated 2025-02-03：PSoC 5LP `CY8CKIT-059`、LCD `NHD-0216BZ`、thermistor `570-1229-ND`、resistor `A105970CT-ND`，另需 breadboard、wire 与 oscilloscope。料号用于核版本，购买前仍以当前 lab handout 为准。到货后先核封装、阻值曲线、LCD logic level 与板卡 revision，任何替代料都要把 electrical difference 写进 BOM diff。

Infineon [`CY8CKIT-059` page](https://www.infineon.com/evaluation-board/CY8CKIT-059) 将板卡标为 active/preferred，并指向 KitProg/PSoC Creator。Infineon 当前的 [PSoC Creator 产品页](https://www.infineon.com/psoccreator) 仍把 Creator 定义为 Windows-based IDE，把 schematic hardware design、firmware、code generation 与 debugging 放在同一环境。这个 host 依赖也是实验条件：环境页列出 OS、Creator build、board revision、KitProg firmware、driver、LCD pin map 与 instrument model，然后分别跑 enumeration、blink/ADC、LCD 与 probe check。port 到 generic MCU 属于迁移练习，最好另建工程与原 PSoC assignment 对照。

兼容性失败正好用来区分软件和电路。USB 未枚举时分别检查 cable、driver、KitProg firmware 与 host policy；ADC example 失败时再区分 pin routing、reference、clock 与 code generation。一次只改一项，把 old value、new value 与 observation 放在一起比较，才能判断问题属于 legacy toolchain 还是 circuit，避免把一次偶然重启写成解决方案。

## 从异常温度一路查回接线

正式材料可用后，以 known-voltage ADC transfer 作为分界：它若不稳定，问题仍在供电、接线、reference 或固件；它若稳定，再讨论 divider、thermistor fit 与 Module 5 collection。重复性超出 uncertainty 时应回查 contact 与 supply，增加小数位不会改善测量。

拟合后观察 residual 是否随 temperature 单调漂移，再区分 model error、self-heating、contact、power variation 与 quantization。校准集与检查集、升温与降温分开后，model fit、hysteresis 与 repeatability 才不会被同一张平均曲线混在一起；截图也只有在 raw ADC code 到 display value 的路径说得通时才有解释力。

若 platform assignment 被锁，公开材料只能支撑到相应断点；换成 Arduino 或其他 MCU 可以练迁移，但 firmware、reference、resolution 与 timing 的变化会让它成为另一套实验，不能借同名抹去差异。

看到异常温度读数时，应能沿原始码值、接线、固件版本与校准条件逐层反查；成功界面要和失败时的 raw code 放在一起看，才知道修复是否真的作用在问题上。

动手范围只到隔离、限流、≤5 V 的桌面电路，改线前断电，也不连接人体、medical sensor、mains、unknown supply 或 exposed heater。NPTEL [Electronic Measurement and Instrumentation](https://nptel.ac.in/courses/108105153)（ID 136）解释 loading 与 uncertainty；本课的独特价值，是在真实访问成立时看见这些误差怎样落进 firmware–ADC–calibration 链。
