## 先选 Fall 2022 档案，还是仍在变化的教材

MIT 6.4210 Robotic Manipulation 的
[OCW 入口](https://ocw.mit.edu/courses/6-4210-robotic-manipulation-fall-2022/)
保存的是 Fall 2022 课程：perception、planning、dynamics/control 和 learning 共同服务于
在 cluttered scene 中操控物体。与此同时，
[在线教材](https://manipulation.csail.mit.edu/) 是 living notes，页面仍写着会在
Fall 2025 学期持续更新。两者内容同源，却不是同一份冻结版本；旧 Problem Set 的题号、
Deepnote notebook 和今天的 `pydrake` API 不能默认逐项相容。

本导读用 Fall 2022 的课程安排定义“学什么、交什么”，用一个明确代码快照定义“今天怎样
运行”。想忠实复盘当年教学时，应保存 2022 题目和 lecture recording 的链接；想使用
当前教材时，则要接受章节、exercise 和依赖会继续漂移。不要一边引用 2022 grading，
一边用后来新增的章节声称自己完成了当年的全部作业。

## 先修页面的两种口径都要看到

[Fall 2022 Course Information](https://manipulation.csail.mit.edu/Fall2022/index.html)
正式列出 basic linear algebra、probability、algorithms、basic neural networks，
以及 Python cloud Jupyter 作业；同页 FAQ 又说课程不要求既有 robotics 经验，并把
basic familiarity with linear algebra 称为唯一 required prerequisite。因此入门门槛
应落在基础线代：能做矩阵乘法、解小型 least-squares，并在 Python/NumPy 中分清 shape
与 broadcasting。Probability、algorithms、neural networks 会让后半程更顺，但不是
据此拒绝开始课程的硬门槛。

Homogeneous transform、Jacobian 和带线性约束的 QP 可以在开课前各看一个小例子，
但只能算 stretch preview。课程会在 kinematics、trajectory optimization 等单元内教
optimization；不会先写 QP 不等于先修不合格。若 Python 和线代同时薄弱，Drake 报错会
与几何错误叠在一起，先补其中一项即可。

## 十份 Problem Set 是逐层长成的软件栈

[Fall 2022 Schedule](https://manipulation.csail.mit.edu/Fall2022/schedule.html)
列出 Problem Set 1–10：Simulation；Kinematics I、II；Geometry I；Geometry II and
Grasping；Simulation and Behavior；Deep Perception；Planning；Control/Project
check-in；Reinforcement Learning。前半不是十个独立 demo，而是在 Drake、MeshCat、
kinematics、point cloud、grasping、state machine、planning 和 control 之间逐层增加
接口。

独立学习可分四段：

1. PS1–PS3 只做 simulation、frame/pose、Jacobian、trajectory 和 optimization，
   先把单位、坐标系和 notebook 输出记清；
2. PS4–PS5 进入 registration、outlier、free-space constraint、clutter 与 grasp，
   每次都保留 point cloud 输入和失败 overlay；
3. PS6–PS8 接 behavior、deep perception 与 motion planning，用固定场景比较
   algorithm choice，而不是只保存成功动画；
4. PS9–PS10 连接 force/manipulator control、project check-in 与 RL，最后检查前面
   notebook 在下文的兼容基线上能否重新运行。

题目页面公开，书面答案、Piazza、Canvas、Gradescope feedback 与 autograder 课程入口
并不对校外学习者等价开放；Deepnote 也需要账号。自建测试应检查 transform 正交性、
collision-free、终止状态和 deterministic seed，并把平台 feedback 的缺失写进记录。
课程信息说有 midterm、没有 final exam，但公开 schedule 没给 midterm 试卷和解答，
不能据此写成“考试资源完整”。

## Final Project 要报告场景分布、碰撞和求解器行为

[Project](https://manipulation.csail.mit.edu/Fall2022/project.html)
把项目限定在 4–5 周，可由 2–3 人组队；允许复现论文或把已有方法用于 manipulation，
不要求算法必须新颖。Preproposal 约 500–750 词，final proposal 约 1000 词；最终 video
按个人、两人、三人分别为 3、4、5 分钟，report 建议 1500–4500 词，并明确要求 abstract、
related work、method、results、discussion 和成员贡献。对 6.4210，assignments 占 40%，
proposal 10%，report 30%，video 10%，另有 journal/peer review 5% 和 CI-M participation
5%；写作不是代码完成后的装饰。

我会从官方 ideas 中选一个 simulation-only 任务，例如 clutter clearing、peg-in-hole
或 motion-planner benchmark。报告应先定义初始位姿、遮挡、质量与摩擦的测试分布，
再按场景分组给出成功率、collision/minimum-distance、solver termination 与 runtime。
视频可以展示代表性轨迹，但不能代替碰撞统计；对 optimization initialization 敏感的
场景要单列。最后用一张 sim-to-real 差异表讨论 calibration、latency、contact 和 sensing，
即使项目完全不接真机也要说明这些缺口。若复用社区代码，报告需区分上游部分与本人修改。

## 给 Drake 和 pydrake 设一条兼容基线

核验日 2026-07-29，EEDIY 选择官方 `manipulation` 仓库的
[commit cdb8c90f402c9201999bb90a27a034cf2e5d166c](https://github.com/RussTedrake/manipulation/commit/cdb8c90f402c9201999bb90a27a034cf2e5d166c)
作为本导读快照。该提交的
[pyproject.toml](https://github.com/RussTedrake/manipulation/blob/cdb8c90f402c9201999bb90a27a034cf2e5d166c/pyproject.toml)
把包版本写为 `2025.10.20`，声明 `python>=3.10,<4.0`（注释点名 3.10、3.12、3.13
三个支持目标），并要求 `drake>=1.45.0`。EEDIY 建议用 Ubuntu 24.04、Python 3.12、
上述源码 commit 和 `drake==1.45.0` 作为当前兼容基线；其中只有 Drake 版本是精确
dependency pin，源码 commit 只是取材快照，其余依赖仍沿用 `pyproject.toml` 的宽范围。
这不是 Fall 2022 原课堂环境，也还不是完整锁定的 2026 环境。

该快照没有随本页提供全传递依赖 lockfile，本导读也尚未发布一次从空 virtual environment
安装并跑完代表性 notebook 的 smoke-test 记录。因此先尝试安装并运行一个最小 smoke
notebook，记录 OS、Python、Drake、manipulation commit、solver 和报错；这只能检验
本机兼容性，不能把“建议基线”写成已验证 lock。Deepnote 账户曾是课程主平台，但云镜像和
项目链接可能变化；下载 notebook 后仍要保留依赖信息。某些 `MathematicalProgram` 题可能
利用有学术许可的 solver，独立学习者没有许可时可在题目允许的范围使用开源 solver，
但必须记录替换、termination、objective 和 constraint residual，不能把不同 solver 的
结果当作完全等价。

## Simulation、Deepnote 和真机不能证明同一件事

课程说班级可为 ambitious final project 提供 hardware，同时大量使用 cloud simulation；
这不表示校外读者可访问 KUKA iiwa、Franka、gripper、camera、机器人驱动端或控制计算机，
也不表示有现场监督。当前教材的 `HardwareStation` 还暴露只在 simulation 中存在的
ground-truth “cheat ports”，
真实 `HardwareStationInterface` 没有这些端口。评测 controller 时不得读取 cheat
ports；它们最多用于离线标注和误差分析。

仿真通过只能证明固定模型、参数和求解器下的行为，不能等同真机的 calibration、
latency、contact、friction、sensor noise 和 safety。独立路线不要求购买机器人，CPU
即可完成大量 kinematics/planning 内容；deep perception 或 RL 的计算成本应通过小数据、
固定训练预算和缓存结果控制。若进入实体机械臂实验，必须由合格实验室负责 risk
assessment、workspace exclusion、限速/限力、急停、碰撞保护和监督。在这条校外路线里，
留下十份公开作业的运行记录和一项 simulation project 即可；它们不证明机械臂能在家中
安全运行，也不补齐原课堂的硬件条件。
