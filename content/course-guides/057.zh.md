## 先把 RP2350、RP2040 和 PIC32 分开

Cornell ECE 4760/5730 不是一门只看嵌入式视频就能完成的课。
[当前课程首页](https://ece4760.github.io/) 把它定义为 Cumulative Design Experience：
2–3 人一组，把微分方程、DSP、模拟电路、控制、图形和机电知识做进实体系统；核验日
写明当前 MCU 是 Raspberry Pi Pico 2 上的 RP2350。可是同一页公开的是 2025、2022
RP2040 录像，还保留 2021 PIC32 旧站入口；一些安装说明和 BOM 也仍写 Pico/RP2040。
芯片外设大体延续不等于寄存器、引脚、SDK 目标和板级接线可以混用。开始时应在仓库
README、CMake target、板卡照片和 datasheet 四处都标明所选版本。

三份实验页的版本标注并不完全相同：Birdsong 明确给出 Fall 2025 的 RP2350 版本，
Galton Board 与 Helicopter 则按核验时可见的当前 RP2350 writeup 使用，不替它们补写
学期。2025 RP2040 录像只作为概念补充。若某段示例只能在 RP2040 编译，就建立单独分支
并记录差异，不要静默修改后声称复现了当前实验。PIC32 项目档案适合找思路，不适合充当
当前 starter code。

## 三个实验不是三份 peripheral demo

课程不是许多零碎 peripheral demo。3 个实验各持续约 3 周，检查点累积，随后进入
4–5 周 final project。

第一个是 [Birdsong](https://vanhunteradams.com/Pico/Birds/Birdsong.html)：用 DDS、
定点数、SPI DAC、keypad 和去抖状态机合成 2–7 kHz 左右的 cardinal song，最终目标不是
“扬声器响了”，而是频谱、扫频时序和交互都达到可说明的规格。随后做
[Digital Galton Board](https://vanhunteradams.com/Pico/Galton/Galton.html) 在 60 fps
VGA 上并发模拟碰撞与二项分布，用 DMA 播放每次撞击的声音；性能通过同时运动的小球数、
帧率和分布误差判断是否达标。最后的
[1D Helicopter](https://vanhunteradams.com/Pico/Helicopter/Helicopter.html) 把 I2C IMU、
互补滤波、PWM、光耦隔离、串口/VGA 和 PID 合成闭环控制，第一周就要求完成机械装配、
开环电机控制和专用电机 PCB。

这个次序有意从确定性波形走到高并发模拟，再走到会伤人、会振荡的物理控制。独立学习
不能只挑最吸睛的 helicopter；缺掉前两项，DMA、定点、显示和调试节奏都会在高风险装置
上第一次出现。

## 第一项工作是编译 demo，并把波形量出来

[Policy](https://vanhunteradams.com/Pico/CourseMaterials/Policy.html) 要求 ECE 3140 或
教师许可，并明确写 C、电子制作和相当数量的数学。不要另造一套抽象的入门测验；先按
当前 RP2350 说明编译一份课程 demo，在 Pico 2 上输出周期 GPIO 或 PWM，再用示波器保存
一张带时间刻度、电压刻度和探头位置的 trace。源码能编译却没有引脚波形，多半是
board target、pin mapping 或供电问题；波形存在但频率不对，才回到时钟、定时器与整数
计算。这个小回路正好同时检查 C/CMake、datasheet、板级接线和测量习惯。

若卡在编译，先补指针、头文件、CMake 与调试器；若 GPIO 正确而 SPI DAC 没输出，就分开
量 SCK、MOSI、CS 和 DAC 端，而不是继续改算法；若看不懂量程、logic level 或时序图，
先练 datasheet 阅读。官方要求每名组员都理解系统的所有部分，独学仓库也应让硬件版本、
控制参数与报告引用同一份配置，而不是分成彼此不一致的三个目录。

## 按硬件风险而非日历复建

第一阶段先锁定 SDK 与 board target，编译课程 demo。可复建记录应写 SDK commit、
编译器/工具链版本、所选 board 或 CMake preset，以及原样可复制的 configure/build
命令；`CMakeCache.txt` 含本机绝对路径和探测结果，不应当作可移植输入。第二阶段做
Birdsong，但先让 DDS 在主机脚本中产生参考频谱，再接 DAC、keypad 和扬声器。

第三阶段做 Galton Board。固定随机种子只用于回归：同一 build 应产生相同小球轨迹，
方便比较帧率和碰撞改动；它不能证明随机过程正确。统计检查要重新运行许多独立种子，
把落点的经验均值、方差和直方图与预期二项分布比较，再加入 VGA、DMA 与声音，并用
时间戳或逻辑分析证明 60 fps 下没有阻塞。实验记录沿用原课的预读、weekly progress、
final demo 与 report 节奏，不另造一套通用工作流。

Helicopter 不应成为无监管学习者的默认实体任务。可先用软件 plant model、录制的 IMU
数据或受限角度的小功率台架验 PID；若确实搭建，应先逐行读
[Motor Circuit](https://vanhunteradams.com/Pico/Helicopter/MotorCircuit.html)：
MOSFET gate 由隔离侧 12 V 驱动，电机使用 5–6 V，处理器与电机侧分别供电且地也不能
相连。电机电流路径绝不能搭在无焊面包板上，要按课程 PCB 装配，并检查 4N35、MOSFET、
续流二极管方向。焊接时戴护目镜并开排烟；台架还要有机械限位或防护、电流限制和急停。
ducted fan 上电前先确认开环方向、PWM 停止态和 IMU 符号。专用 PCB、课程台架和现场
TA 都不是公开网页自动提供的条件。

## Final project 按 proposal、周报、demo 与网页推进

[Final Project](https://vanhunteradams.com/Pico/CourseMaterials/Final_Project.html) 要求
2–5 页 proposal、暂定成本、框图/原理图、社会影响、标准、安全、IP 和无线合规考虑，
之后每周报告上周成果、下周目标和投入时间。官方建议最后 4–5 周每周约 16–20 小时，
这是正规 4 学分团队课的负荷，不应伪装成周末小项目。最终网页要让技术读者凭文档重建，
并包含测试数据、scope trace、速度/精度、失败尝试、AI 使用、代码来源与成员分工。

课程总评是 labs 50%、final project 50%。每个 lab 内部又分为 debugging quiz 10%、
weekly progress 20%、final demo 30%、report 40%；这也解释了为什么一段能运行的代码
只完成了实验的一部分。项目页顶部目录把 project 写成 progress 20%、demo 30%、
report 50%，但正文与当前 policy 都写 preparedness 10%、progress 20%、demo 30%、
report 40%。正文和当前 policy 彼此一致，因此本页采用 10/20/30/40，同时把旧目录
冲突留在记录中。

独学时不需要虚构 Cornell 分数，可以直接沿着原课四项检查：proposal 是否把器件与风险
准备齐；每周记录是否能看出真实进展；demo 能否从断电状态重复；HTML report 是否给出
scope trace、速度/精度数据、失败尝试与硬件—软件取舍。这样保留课程本来的设计节奏，
而不是给任何项目套同一张打勾表。

历届项目网页从 1999 延伸到 2025；当前列表仅 2025 就包含音频定位、BLDC 控制、
示波器、机器人、视觉和网络项目。它适合校准复杂度与报告格式，但复用代码必须逐项
归因；课程 policy 也禁止实验组之间共享未保护的代码，公开 final project 代码仍须
详细标注来源。

## 预算、安全与公开材料缺口

最低实验包不只是 Pico 2：还会涉及面包板/洞洞板、跳线、USB-UART 或调试器、VGA
显示、DAC、keypad/encoder、IMU、电机驱动、机械件、电源与测量工具。课程链接的旧 BOM
仍列原始 Pico、micro-USB 和共享显示器，不能当作 RP2350 当前个人采购单。先为每个
实验做单独 BOM，核对逻辑电平与供货，再询价；final project 还必须设费用上限和可替代
器件。没有示波器、稳压限流电源或安全台架时，完成前 2 项的软件/低压部分并交出
仿真 helicopter，优于冒险复制实体装置。

官方公开课程站能让访客取得 lab writeup、demo code、datasheet、讲义链接和大量学生
报告，但拿不到 Canvas 提交、现场设备、TA checkoff 或 Cornell 配发材料。完成后应能
看到 3 个实验各自的版本锁、源码、原理图、原始测量、检查点记录和报告，以及 final
project 的 proposal、BOM、风险表、每周状态、演示视频与 HTML 报告。只编译几个
peripheral demo 仍是准备阶段，不能代表这门课要求的累计设计经验。
