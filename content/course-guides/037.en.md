## Do Not Blend Two 6.004 Offerings into One “Complete Version”

MIT OCW preserves both Spring 2017 and Spring 2009. The
[2017 course home](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2017/)
is the better teaching source: 21 topic units move from information and the
digital abstraction through CMOS, combinational and sequential logic, the
Beta, caches, pipelines, virtual memory, interrupts, concurrency, and
parallel processing. Most units include annotated slides, topic videos, and a
worksheet. However, the
[2017 syllabus](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2017/pages/syllabus/)
mentions seven labs and an end-of-term design project while the public
navigation exposes no corresponding lab or checkoff files. It also specifies
four closed-book quizzes and no final.

The 2009 offering is the executable laboratory archive. Its
[syllabus](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2009/pages/syllabus/)
specifies eight labs, an optional design project, five quizzes, no final, and
Athena/JSim/BSim. This guide therefore makes an editorial composite: 2017
teaching with 2009 labs and problems. It does not combine the two years’ lab
counts, grading, or exams into a fictitious semester. Notes, code, and score
sheets must retain the year.

## Run the Old JRE Only inside an Isolated Environment

The 2009 [tools page](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2009/pages/tools/)
publishes `jsim.jar`, `bsim.jar`, `tmsim.jar`, Beta macros and includes, and
lab checkoff files. Its instructions still reference Sun J2SE, older Windows
and OS X, and `-Xms8m -Xmx32m`. Public files are not a guarantee of
compatibility with a 2026 Java runtime. If an old JRE is required, put it in a
dedicated VM with networking disabled, run it as a non-administrator, and
mount no writable host directory or shared clipboard. Download course inputs
and verify their hashes before detaching the network. To retrieve output,
shut the VM down first and use a temporary export image; the old Java process
should never write directly into the host workspace.

The first run needs only one JSim smoke test: load the nominal device model
from the tools page, confirm that it opens, evaluates, and saves a minimal
result, and record OS, JRE, launch arguments, and file hashes. Start TMSim and
BSim when the route reaches the Turing machine and Beta rather than inventing
three premature tool exercises. If the GUI needs the old JRE, freeze that VM
instead of upgrading halfway through.

Logisim, Verilog, or a modern RISC-V implementation can be useful, but each is
a port rather than direct completion of the original lab. Preserve a reference
output from the JSim/BSim input before making an HDL version. Every official
lab here is simulated; no FPGA, breadboard, mains supply, or “Beta development
board” is required. Cost is essentially compute and storage, not hardware.

## Connect the Unit 1 Worksheet to the First JSim Circuit

Download the annotated slides and worksheet for 2017 Unit 1. Complete a first
worksheet attempt without solutions, then perform the nominal-model JSim
smoke test in the isolated VM. The worksheet reveals gaps in binary
representation, the digital abstraction, or static discipline. The smoke
test answers only whether the legacy tool runs. Use the corresponding topic
video for a concept block and runtime, path, or launch diagnostics for a tool
block; do not collapse both into “I cannot learn architecture.”

Pair the eight 2009 labs with the point at which the 2017 sequence makes them
useful:

1. **Units 1–8 + Labs 1–3:** CMOS, Adder, and ALU. Keep a truth table, timing
   assumptions, JSim netlist, checkoff output, and one deliberately injected
   fault for each circuit. Explain propagation delay and static discipline
   from the circuit rather than copying a worksheet sentence.
2. **Units 9–13 + Labs 4–6:** Turing machine, Assembly, and Beta. Establish
   state-machine semantics with a TMSim transition table, then test
   arithmetic, branches, loads/stores, and an illegal opcode in BSim with
   original instruction sequences. Explain PC, register-file, and control-ROM
   behavior from traces.
3. **Units 14–21 + Labs 7–8:** Trap handler and Tiny OS. Bring caches,
   pipelines, virtual memory, interrupts, and concurrency back to the same
   Beta. Decide whether to attempt the optional 2009 project only after this
   sequence.

The [2009 labs page](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2009/pages/labs/)
does publish the eight PDFs, JSim/BSim documentation, and Beta references.
The original course also used staff interviews, online questions, and a
checkoff service that outside learners cannot access. Replace that feedback
with a recorded oral defense: without reading code, explain the interface,
critical state, worst-case timing, and one failed test for each lab.

## Problems and Exams Expose “The Simulator Ran” as an Incomplete Claim

The [tutorial problems](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2009/pages/tutorial-problems/)
are grouped around five quizzes and include solutions. They cover the digital
abstraction, CMOS, FSMs and metastability, pipelines, machine language, the
Beta, caches and VM, interrupts, semaphores, and the pipelined Beta. After
each study step, save the uncorrected tutorial attempt before checking
solutions, then take its historical quiz under a time limit.

The [2009 exams page](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2009/pages/exams/)
provides question papers and solutions for Quizzes 1, 2, 3, and 5, but only a
solution for Quiz 4. Preserve that gap: four papers can be timed and scored;
the Quiz 4 solution can only be reverse-indexed into concepts. Do not invent a
“complete five-exam average.” The 2017 worksheets add newer conceptual
practice but are not 2017 official quiz papers.

## Explain the Beta with Instruction Traces, Not a Run Screenshot

Using the official 2017/2009 material above, the final repository should
contain a version map and fixed tool environment, concept maps for all 21
units, original and corrected netlists or assembly for eight labs, test
vectors, checkoff outputs, critical traces and fault logs, and first attempts
plus an error index for four scoreable historical quizzes. “It runs a
program” is not enough for the Beta. For a suite of short programs, compare
every instruction against a reference trace and record expected and observed
behavior at reset, taken and untaken branches, memory boundaries, interrupts,
and illegal instructions. Keep the commands and terminal output that
reproduce the trap handler and Tiny OS from a cold start.

As an optional editorial extension—not an MIT assignment—port the ALU or one
unpipelined-Beta submodule to Verilog/SystemVerilog and compare JSim with RTL
bit for bit using identical vectors. Explain differences in abstraction,
unknown values, combinational loops, and timing models. This retains a
checkable historical baseline while transferring the skill to modern tools,
instead of silently changing tools and losing the original problem’s
semantics.

## The Editorial Choice and Its Cost

As an editorial choice, if limited to one official release, I would choose
2017 for first learning because its videos, annotated slides, and worksheets
have useful granularity. To build
anything resembling “gates to a computer,” add the separate 2009 laboratory
track. This pairing is more useful than two bare OCW links, but it was never
one MIT semester.

Prerequisite language also differs. The 2017 page lists 8.02 and assumes
basic programming and electrical fundamentals in prose; 2009 names C or
6.001, 6.002, and an Athena account more directly. An outside route needs no
Athena account, but it inherits legacy-tool compatibility, absent checkoffs,
and the missing Quiz 4 paper. Put one explicit sentence in the final README:
“theory from Spring 2017; labs, tools, tutorials, and exams from Spring
2009.” Without that version statement, even a working Beta does not tell a
reviewer what was completed.
