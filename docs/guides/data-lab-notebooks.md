# 数据与实验记录

实验日志最难补写的，往往不是结论，而是当时被认为“肯定记得”的细节：示波器探头是 1× 还是 10×，固件是哪次提交，CSV 的时间列究竟是秒还是毫秒。等到曲线异常时，缺少其中任意一项都可能让一次测量失去解释力。

因此不要从选择某款电子实验记录软件开始。先选一个很小的测量，例如低压 RC 阶跃响应，然后要求自己能从报告中的一个点反向找到：哪一次运行、哪份原始文件、什么接线与设置、经过哪段代码，最后为什么进入这张图。

## 先问清楚：这一行数字是怎么来的

每次上电前分配一个短而稳定的 `run_id`，并记录 UTC 时间、硬件修订、固件提交、仪器型号、探头倍率、量程、采样率、激励、环境条件和校准依据。`run_id` 是连接记录的键，不应把所有条件都塞进一个越来越长的文件名；条件变了就生成新运行，记录写错则追加更正说明，不回头改成“仿佛当时就是这样”。

原始 CSV 旁边放一份机器可读的数据字典，至少规定列名、类型、单位、允许范围、缺失值表示和时间基准。W3C 的[表格数据模型](https://www.w3.org/TR/tabular-data-model/)说明了怎样为表、行、列和单元格附加元数据，也把验证与显示视为不同处理。小项目不必实现整套标准，但应借用这个思路：单位和约束属于数据接口，不能只写在人的记忆里。

一份够用的运行记录可以回答这些问题：

| 对象 | 至少要留下什么 | 何时真正有用 |
| --- | --- | --- |
| 被测对象 | 板卡/器件编号、修订、连接图 | 两块“同型号”板行为不同时 |
| 采集链 | 仪器、通道、探头、量程、采样设置 | 判断饱和、混叠或倍率错误时 |
| 时间 | UTC、设备相对时间、触发点 | 合并多设备数据时 |
| 数据 | 文件校验和、模式版本、缺失说明 | 文件被移动、重命名或损坏时 |
| 处理 | 脚本提交、参数、输入与输出 ID | 图与原始测量对不上时 |

## Notebook 只能解释数据，不能改写发生过的事

采集程序完成一次运行后，先关闭文件并计算校验和，再允许分析程序读取。`data/raw/` 只保存仪器导出和采集时写下的元数据；去基线、重采样、滤波和单位转换写入 `data/derived/`。原始文件即使有坏行也不“顺手修掉”，而是由转换脚本明确报告坏行、处理策略和新输出。这样才能区分“仪器当时给了什么”和“后来怎样解释它”。

Jupyter 适合把公式、图和讨论放在一起，却不适合作为唯一的时间线。单元格可以乱序运行，内存里也可能残留旧变量。让 notebook 调用普通脚本中的读取与分析函数，并能从空 kernel 顺序执行；采集日志、原始文件和参数另存。若处理链跨越多份数据或多人协作，可用 W3C [PROV-O](https://www.w3.org/TR/prov-o/) 中 Entity、Activity、Agent 的关系来检查自己的命名：输入实体被某项活动使用，产生另一个实体，并关联执行者或软件。这里需要的是清楚的来源关系，不是为了一个 RC 实验搭建知识图谱。

记录是否有效，有一个直接测试：随机挑最终图中的一点，能在几分钟内定位到派生表的一行、转换参数、原始行和对应运行设置。只找到 notebook 截图不算通过；只找到同名但校验和不同的 CSV 也不算。

可以先用仓库里的 [RC 低通离线 starter](https://github.com/appleweiping/eediy/tree/main/examples/rc-lowpass)练这条追踪链。它生成的 `manifest.json` 明写 `analytic_reference`、单位、参数、行数与 CSV 的 SHA-256；测试还会篡改一行数据，确认分析在校验和不匹配时停止。这里没有仪器记录，不能把这份 manifest 当成测量日志。

## 用三次 RC 阶跃把记录中的漏洞逼出来

使用合成数据，或在受限低压条件下采集三次 RC 阶跃。先写下电阻、电容的标称值与容差、预计时间常数、采样率和停止条件，再开始运行。三次运行可以保持电路不变，也可以有意改变一次采样率；关键是每次都有独立 ID，而不是把三条曲线贴进同一张表后丢掉来源。

随后让自动检查主动遇到三种坏输入：

- 把一份文件的时间单位从 `ms` 标成 `s`，范围或数量级检查应在拟合前停止；
- 复制一个 `run_id`，唯一性检查应指出冲突的两条记录；
- 删除探头倍率或校准日期，记录应被标为信息不足，而不是悄悄采用默认值。

对正常数据，用同一脚本估计三次时间常数，报告重复性，并列出仪器分辨率、元件容差或校准带来的其他不确定度。NIST [Technical Note 1297](https://www.nist.gov/pml/nist-technical-note-1297)区分由统计方法评定与由其他信息评定的不确定度分量，并说明组合与报告方法；它适合在你已经明确被测量和输入量之后使用，不是给标准差换一个更正式的名字。有效的结果不是“小数位很多”，而是数值、单位、不确定度和适用条件能一起被复算。

## 能复算不等于可以公开

准备共享时，先把“别人需要复算的内容”和“没有权利公开的内容”分开。个人身份、健康、位置、密钥、厂商保密模型以及受许可证限制的数据，不应因为项目用了公开仓库就被带出去。对人体或患者数据，自学项目应使用合法公开且去标识的数据集；是否去掉姓名并不足以判断重新识别风险。

若数据已经适合长期发布，再补充稳定的题名、创建者、发布者、年份、资源类型、版本、权利和相关资源标识。DataCite 的[元数据模式](https://schema.datacite.org/)可以用来检查哪些信息让数据可被识别、检索和引用；它服务于发布阶段，不能替代采集时的探头设置和异常记录。第三方数据的引用与再分发许可也要分别判断，能引用不代表能把原文件重新打包。

最后从一个空目录重跑分析，并请另一台机器只根据运行记录找到同一输入。若大型原始文件不能公开，可发布模式、字段说明、校验和、生成一份小型合成样例的方法，以及申请合法访问的路径。之后可把分析入口接入[可复现工程](reproducibility.md)，或在[技术写作](technical-writing.md)中把图的来源写进报告。
