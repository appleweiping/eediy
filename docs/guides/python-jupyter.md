# Python、Jupyter 与工程计算

本页只分析一份 RC 阶跃数据，不罗列 Jupyter 功能。打开 notebook 之前就确定输入、待估参数、两种估计方法和数值容差；图和拟合随后用来回答这些问题，不能在看到漂亮曲线后再改合格标准。

| 记录项 | 开始计算前写下的内容 |
| --- | --- |
| 输入 | 只读 CSV、时间/电压单位、采样间隔与校验和 |
| 待估参数 | RC 时间常数 \(\tau\) |
| 方法 | 相对阶跃起点 \(t_0\) 的 \(1-1/e\) 阈值插值与指数模型拟合 |
| 合成数据验收 | 例如 \(\lvert\hat{\tau}-\tau_\mathrm{ref}\rvert \le \max(0.02\tau_\mathrm{ref}, \Delta t)\)，阈值须在看结果前确定 |
| 实测数据验收 | 按采样、噪声、仪器和模型不确定度预先给出容差，不照搬合成数据的 2% |

这个小实验同时需要公式、数组、数据检查、拟合、残差和单位，却不需要昂贵硬件。Python 官方[教程](https://docs.python.org/3/tutorial/index.html)可以补语言基础；已经能写函数和读文件的人，不必为了开始记录先读完整套教程。

## 关键计算放进函数，而不是藏在单元格状态里

把读取、检查、估计和作图分别写成普通 Python 函数，笔记本只负责选择输入、调用函数并解释结果。这样做不是为了追求“工程化”，而是为了让计算能被测试，也能在没有浏览器界面的机器上重跑。数组操作可从 NumPy 的 [Quickstart](https://numpy.org/doc/stable/user/quickstart.html)按需查阅；尤其要弄清 shape、axis、切片和 broadcasting，不能凭一张看起来平滑的曲线判断维度正确。

一个够用的目录可以很小：

```text
rc-step/
├── data/raw/step.csv
├── src/rcfit.py
├── notebooks/rc-step.ipynb
├── tests/test_rcfit.py
└── results/
```

`data/raw` 中的输入只读；`results` 可以删除后重建。读取函数应检查列名、有限数值、时间严格递增和采样间隔，并明确文件中的时间是秒还是毫秒。计算内部统一单位，展示时再选择合适的 SI 前缀。变量名带 `_s`、`_v` 之类的单位后缀虽然不完美，却比无声猜测强得多。

## 用两种方法估计同一个时间常数

先生成一份已知 \(\tau\) 的合成阶跃数据，固定随机种子；有安全的低压测量条件时，再换成真实 CSV。先从输入通道或明确的触发标记确定阶跃起点 \(t_0\)，再插值得到输出达到最终变化量 \(1-1/e\) 的时刻 \(t_{63.2\%}\)，阈值法的估计是 \(t_{63.2\%}-t_0\)，不能把触发延迟并入 \(\tau\)。第二种方法使用带 \(t_0\) 或延迟参数的指数模型拟合。若采用 SciPy，可直接查官方 [`curve_fit` 参考](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.curve_fit.html)，同时写清初值、参数界限和返回的协方差信息；“优化器收敛”并不等于参数具有物理意义。

仓库中的 [RC 低通离线 starter](https://github.com/appleweiping/eediy/tree/main/examples/rc-lowpass)把 \(t_0\) 故意设为 2 ms，并用纯标准库脚本同时输出绝对过阈时刻和扣除触发延迟后的 \(\tau\)；它适合直接检查自己的实现有没有把两者混为一谈。

在图上同时画原始点、拟合曲线和残差。报告采样率、估计的 \(\tau\)、两种方法之差，以及阈值插值和拟合各自依赖的假设。然后故意制造三类坏输入：

- 删除一个必需列，读取阶段应直接报错；
- 打乱时间顺序，不能让后续拟合默默继续；
- 把毫秒数据当成秒，数值测试或量纲检查必须抓住三个数量级的偏差。

对小数组先手算一遍。NumPy 在 shape 不匹配时可能合法 broadcasting，结果尺寸甚至看起来合理；在函数入口断言维度，比在最后一张图上猜错在哪里有效。拟合残差若随时间呈现结构，先检查模型、基线、延迟和采样，而不是继续增加小数位。

## 重启内核以后从第一格重新运行

Jupyter 官方的[安装与使用入口](https://docs.jupyter.org/en/latest/install.html)说明 Notebook、JupyterLab 与 kernel 是不同组件。为项目创建独立环境并记录实际 Python 与包版本，不要只写“使用最新版”。清空输出、重启 kernel、从第一格顺序执行；如果这一步失败，说明笔记本依赖隐藏状态。把修复落回 `src/` 和测试，不要再添加一个“请先运行第 17 格”的提示。

还要从命令行提供一个入口，能由原始 CSV 重新生成结果表、图和一段文本摘要。输出文件写入独立目录，图轴带单位，曲线除颜色外再使用线型或标记区分。静态摘要应回答“估计是多少、误差多大、模型在哪些地方不合”，让不运行 notebook、使用屏幕阅读器或处于低带宽环境的读者也能理解结论。

环境锁定也要适度。保留依赖清单和实际版本快照，但不要把解释器、缓存和整个虚拟环境提交进仓库。若分析必须跨平台复现，先在第二个干净环境运行，再决定需要锁到补丁版本还是只约束兼容范围。

## 合成数据跑通以后再连接仪器

合成数据练习走通后，才把输入替换成串口、示波器导出或数据采集接口。采集程序要明确量程、采样率、总时长、超时和安全默认状态；异常退出不能让电源、加热器或执行器继续保持上一次命令。原始数据保存后不覆盖，清洗与滤波步骤写入代码，并在图表旁说明删掉了什么。

归档前在干净环境执行一次命令行入口。对同一输入，\(\tau\) 应落在事先规定且有物理依据的数值容差内，残差指标和预期失败测试也应一致；“数量级相同”不能算同一结果。记录同时包含随机种子、单位、依赖版本、拟合参数、容差依据和方法限制。若结果涉及患者、可识别个人或受限设备数据，不要把原始记录或密钥放进笔记本输出。

完整记录的元数据字段可按[数据与实验记录](data-lab-notebooks.md)组织，重放命令与比较规则可按[可复现工程](reproducibility.md)接入自动检查。数值拟合只能支持数据范围和已声明假设内的结论，也不能替代高能量硬件所需的额定值、保护和现场监督。
