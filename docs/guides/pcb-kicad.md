# PCB 与 KiCad 工作流

本页用一块 3.3 V TMP117 温度传感器小板走完整个流程。它包含传感器、I²C 上拉、地址配置、去耦、ALERT 和主机连接器，规模不大，却足以暴露连接器视角、封装编号、回流、热布局和制造层错误。ERC 与 DRC 很有用，但它们只能覆盖其中一部分。

| 阶段 | 核对内容 | 发现问题时 |
| --- | --- | --- |
| 器件与封装 | 数据手册引脚/封装核对表、固定的 KiCad 与库版本 | 暂不画原理图 |
| 原理图 | 接口表、逐项解释的 ERC、符号—焊盘复核 | 暂不开始布局 |
| 布局 | 制造规则、回流/热/装配检查、逐层 DRC | 暂不导出生产包 |
| 制造文件 | 独立查看过的 Gerber/钻孔/BOM/坐标与校验和 | 暂不下单 |
| 首次上电 | 断电检查、限流计划、逐步测量记录 | 异常即断电并回到故障定位 |

不制板也可以完成制造文件检查。实体上电只使用受限电流的安全低压电源；这张表不适用于高能量或受监管硬件。

## 固定版本、库和实体封装

截至 2026 年 7 月，KiCad 官方稳定版是 [10.0.5](https://www.kicad.org/blog/2026/07/KiCad-10.0.5-Release/)。工程应写明实际使用的完整版本，而不是只写“KiCad 10”；不同补丁版、全局库和第三方插件都可能改变导出结果。把 `.kicad_pro`、`.kicad_sch`、`.kicad_pcb`、项目专用符号与封装一起纳入版本控制，并优先用 `${KIPRJMOD}` 引用项目内的 `.kicad_sym` 与 `.pretty` 库。不要在准备下单时顺手升级工程格式。

练习器件采用 [TI TMP117 数据手册](https://www.ti.com/lit/ds/symlink/tmp117.pdf) 中的 DRV（WSON-6）封装。先从原始资料抄出一张很短的器件表，而不是凭库名称猜：

| 项目 | 要从资料确认的内容 |
| --- | --- |
| 引脚 | SCL、GND、ALERT、ADD0、V+、SDA 的编号；ALERT 与 SDA 是开漏端 |
| 电源 | 推荐工作范围与绝对最大额定值不是一回事；本板选 3.3 V |
| 封装 | 顶视图/底视图、焊盘编号、裸露焊盘处理、阻焊和钢网建议 |
| 应用 | 去耦位置、I²C 上拉、ADD0 接法，以及传感器周围的热路径 |

创建或选用封装后，用封装编辑器逐个点亮焊盘并对照数据手册机械图。再打印 1:1 图或在装配商的封装预览中复核尺寸。这里要解决的是“这个实体器件能否按正确方向焊到这些网络上”，3D 模型好看并不能回答这个问题。

## 接口表与原理图应当互相核对

[KiCad 10 原理图编辑器手册](https://docs.kicad.org/10.0/en/eeschema/eeschema.html) 解释了 ERC、未连接标记、电源符号和项目库的行为。画图前先写接口表：主机连接器的每一脚、信号方向、逻辑电压、板端还是线缆端视角、上拉位于哪一侧、预期测试点都应明确。对于这个小板，至少应能回答以下问题：

- 主机断开时，SDA、SCL 和 ALERT 是否仍有确定状态？若主机也带上拉，并联后的等效阻值是否仍满足总线电流与上升时间要求？
- ADD0 的连接对应哪个地址？配置不能只藏在铜皮里，应在原理图注释和丝印中看得见。
- 连接器的 pin 1 从插合面看还是从焊接面看？符号编号与实物图是否一致？
- 哪些脚确实故意悬空？用 no-connect 标记表达意图，不要用它消掉尚未理解的 ERC。
- 3.3 V 从哪里来、允许的电压范围和最大预期电流是多少？测试点能否在不碰相邻引脚的情况下接触？

`PWR_FLAG` 只是在 ERC 中声明某网络由电源驱动，不能制造电源，也不能证明极性正确。每条 ERC 信息都应回到电路含义：缺少驱动端通常要修连接或电源建模；确属器件模型限制的例外，应在该处写一句局部说明。完成原理图后，再从符号引脚到封装焊盘做一次独立的编号核对。

## 布局还要考虑回流、热路径和装配

[KiCad 10 PCB 编辑器手册](https://docs.kicad.org/10.0/en/pcbnew/pcbnew.html) 涵盖板框、网络类、间距、覆铜区和 DRC。真正的设计规则还要来自拟下单厂家的层叠、最小线宽/间距、最小孔径、阻焊桥和板边要求；不要把 KiCad 默认值当成制造能力。

这块板可以按下面的顺序布局：

1. 先锁定板框、安装孔和连接器。检查插头外壳、手指空间、pin 1 标记及板边突出量。
2. 把 TMP117 放在代表被测环境的位置。若目标是环境温度，别让稳压器、LED 或大面积热铜紧贴传感器；若目标是测 PCB 温度，则要有意设计其热耦合。
3. 将去耦电容靠近 V+ 与 GND，使供电电流环路短而明确。先规划连续参考平面，再布 SDA、SCL 和 ALERT；不要让它们跨过参考平面的缝隙。
4. 按制造能力和电流建立少量有含义的网络类。低速 I²C 不需要为了“高级感”随意声明阻抗控制，但仍要避免长支路、连接器旁无回流和不必要的串扰路径。
5. 给 3V3、GND、SDA、SCL、ALERT 留有标识的测试点，同时检查探头能否落下、夹具能否接近、焊接返修是否有空间。

DRC 能发现间距、未布线、孔到铜等形式问题，却看不懂连接器视角、传感器自热、回流绕路或探头无处可接。用 2D 层视图逐层看铜、阻焊、丝印、板框和钻孔，再用 3D 视图检查器件朝向与机械干涉；两者回答的问题不同。

## 在 KiCad 之外重新查看制造文件

[KiCad 10 命令行手册](https://docs.kicad.org/10.0/en/cli/cli.html) 给出了可自动运行的 ERC、DRC 和导出命令。下面的命令适合放进项目脚本或 CI；文件名按自己的工程替换：

仓库里的 [TMP117 KiCad 可执行起点](https://github.com/appleweiping/eediy/tree/main/examples/tmp117-kicad) 已包含现代源工程、项目内符号/封装库、布线后的两层 PCB、精确引脚审计和制造文件导出器。KiCad 8 及以上版本用一条命令重建 `build/`，任何 ERC、DRC 或原理图—PCB 一致性问题都会返回非零状态：

```bash
python examples/tmp117-kicad/export.py --require-kicad
```

这个示例没有下单动作；TMP117 裸露焊盘、实际连接器、上拉等效值、热响应和制造规则仍是明确的人工复核边界。

```bash
kicad-cli sch erc --exit-code-violations -o build/erc.rpt sensor-node.kicad_sch
kicad-cli pcb drc --exit-code-violations --schematic-parity --refill-zones -o build/drc.rpt sensor-node.kicad_pcb
kicad-cli pcb export gerbers -o build/gerbers sensor-node.kicad_pcb
kicad-cli pcb export drill -o build/gerbers --generate-map --generate-report sensor-node.kicad_pcb
```

`--exit-code-violations` 让规则问题变成非零退出码；`--schematic-parity` 检查 PCB 与原理图的一致性；`--refill-zones` 避免用旧覆铜结果运行 DRC。自动化只负责稳定地重复动作，不能替你解释被排除的问题。排除项应少而局部，并附上对应的数据手册或制造规则理由。

导出的 Gerber、Excellon 钻孔、BOM、贴片坐标和装配图要在独立查看器中重新打开。逐层确认板框只出现一次、铜层和阻焊层方向正确、镀通孔与非镀通孔没有混淆、钻孔落在焊盘中心、丝印没有压住裸露焊盘。最后记录 KiCad 完整版本、导出命令和制造包校验和；这样修改一根网络后，可以判断文件究竟有没有重新生成。

## 首次上电从断电检查开始

收到板子后不要先插主机。先对照装配图做目视检查，确认器件方向、焊桥、缺件、错料与连接器 pin 1；在断电状态测电源轨对地电阻，并把结果与电路预期比较。不存在适用于所有电路的“高于某个欧姆就安全”，但近似短路或与同批板差异很大的读数必须先定位。

第一次只接 3.3 V 与 GND，电源限流值应高于预计静态电流、又明显低于走线和器件可能承受的故障电流。观察电源是否进入恒流、板端电压是否塌陷、器件是否异常升温；闻到异味、看到烟、发现极性错误或电流超出预算时立即断电。不要在带电板上用电阻档，也不要靠手指触摸来判断可能危险的温度。

电源轨正常后，再接主机并依次确认空闲电平、I²C 地址、寄存器读写和 ALERT 行为。若总线被拉低，先断开主机区分故障在板端还是主机端，再检查焊桥、上拉电压、器件方向与引脚复用。最小输出应包括源工程与项目库、器件引脚核对表、ERC/DRC 报告、独立查看过的制造包、首次上电的电压/电流记录，以及每个异常对应的定位过程。

这个练习只覆盖安全低压、受限电流的板卡。市电、较高电压、锂电充电、储能、电源变换、射频功率或人体连接会引入绝缘、温升、保护和法规问题，不应作为无监督的第一块板；软件里的间距、保险与接地默认值也不能代替相应设计。

项目记录最后应列出仍未解决的偏差和暂停下单或上电的理由，而不是只留一个“DRC 通过”的截图。板级观测方案可按[仪器、测量与不确定度](instrumentation-measurement.md)设计；若电源或模拟网络的预期仍说不清，[SPICE 电路仿真](spice-simulation.md)应先给出可检查的工作点与响应预测，实体上电继续等待。
