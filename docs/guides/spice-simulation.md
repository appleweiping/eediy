# SPICE 电路仿真

SPICE 最容易教会人的坏习惯，是先点 Run，再从波形里挑一个像答案的结果。换一种顺序：在打开求解器前，先写下节点电压的数量级、主要极点的位置，以及阶跃响应应当向哪个方向走。仿真负责检验这些判断，不负责替你发明判断。

工具不必统一。ngspice 的[文档入口](https://ngspice.sourceforge.io/docs.html)提供当前手册和历史版本，[官方教程](https://ngspice.sourceforge.io/tutorials.html)给出较短的入门实例；喜欢图形界面可以查看 Analog Devices 的 [LTspice 技术指南](https://www.analog.com/en/resources/design-tools-and-calculators/ltspice-simulator/ltspice-recommended-reading-list.html)。真正需要保持一致的是网表、模型、参数、分析条件和结论之间的关系。

## 先在纸上留下三个会被推翻的预测

选择一个安全的小信号有源低通或两级放大器。画清电源、参考地和每个节点的直流通路，然后手算三个量：静态工作点与器件工作区，中频增益的数量级，以及最可能主导带宽的极点。把输入幅度、源阻抗、负载、温度和采用的器件近似写在旁边。预测不必精确，但必须具体到仿真能够反驳。

先只用理想 R、C 和受控源建立最小电路。这个版本用于检查拓扑和符号；一开始就加入复杂厂商模型，会把接线错误、模型错误和数值问题混在一起。网表中的参数集中定义并带单位，原理图若由 GUI 生成，也要导出一份可读网表，确认实际仿真的节点和元件与屏幕一致。

工作点若不合理，不要继续看 AC 图。检查偏置电流、每个器件功耗、输出余量和线性化位置。只有这些成立，小信号结果才有意义。一个放大器在零输入时已经饱和，仍可能产生漂亮的 AC 曲线，因为求解器忠实地在错误工作点附近线性化。

## 让 `.op`、AC 和 transient 回答同一个问题

以手算工作点作为 `.op` 的第一条比较。然后做 AC sweep，提取中频增益、截止频率和相位，不只截图；使用 measurement statement 或脚本把数值写入文本。改变负载或关键电容前先预测曲线怎样移动，再做参数扫描。扫描步数以能分辨趋势为准，点很多并不会让错误模型变真。

transient 中给信号有限的上升时间，并把观察窗口覆盖到预期时间常数之后。检查削顶、slew、启动和 settling；AC 与 transient 对不上时，先比较输入幅度、偏置、初始条件和线性化假设。对一阶网络，还可以把解析解、AC 截止频率与阶跃时间常数放在同一份短报告中，三者应指向相容的参数。

仓库中的 [RC 低通离线 starter](https://github.com/appleweiping/eediy/tree/main/examples/rc-lowpass)给出可批处理的 ngspice 网表，同时保留独立的解析生成器。网表运行 `.op`、transient 与 AC，打印 \(t_0\)、63.2% 时刻、扣除延迟后的 \(\tau\) 和半功率截止频率；README 明确区分解析参考、仿真输出和仓库中并不存在的实测数据。

接着制造一个故障，例如断开偏置回路、让一个节点失去直流路径，或把负载改到超出设计范围。原有检查必须明确失败。若故障只让图“变得有点难看”，却没有任何量化条件触发，说明仿真流程仍依赖人的事后挑选。

## 收敛错误通常在告诉你电路哪里不自然

singular matrix 常来自浮置节点或缺少直流回路；时间步不断缩小常与理想开关、突变源、刚性模型或不现实的寄生组合有关。先删回最后一个能工作的最小电路，逐项恢复元件。盲目放宽 `reltol`、`abstol` 或最大步长，可能只是让求解器接受一份不可信的轨迹。

加入晶体管、运放或电源芯片模型时，保存获取页面、型号、版本或校验信息、温度范围和许可边界。公开可下载不一定允许把模型重新分发到仓库。不同求解器对方言和扩展语法的支持也不同；Sandia 的 [Xyce 文档与教程](https://xyce.sandia.gov/documentation-tutorials/)同时提供用户指南、参考手册和网表转换资料，适合在需要批处理或跨求解器时查清具体兼容性，而不是假定一个 `.cir` 文件到处等价。

模型升级也应当像设计变更一样审阅。固定输入和 measurement，再切换模型版本，比较工作点、带宽、峰值、功耗和收敛行为。差异可能来自更准确的器件特性，也可能来自引脚顺序、参数默认值或单位错误。先定位差异来自哪里，再决定新结果是否更可信。

## 仿真的终点在上电之前

最后保留原理图源文件、文本网表、求解器与模型来源、手算预测、批处理命令、原始数值输出和一段误差说明。再做一次元件容差或温度变化，报告最差条件及其触发原因，不要只展示 typical。从空输出目录运行批处理命令，应能重建全部数字；报告中同时指出哪些结果仍依赖未建模的封装、布局、热或制造效应。

这里必须停一次。仿真地不等于保护地，理想电源不包含实验室接线和故障能量，器件 absolute maximum 也不是推荐工作点。不得因为波形通过就直接连接市电、大型储能、高功率 RF、激光或旋转负载；这些工作需要合格设施、受训监督、独立保护和实体测量。若目前没有这些条件，就把项目明确收束为仿真结论。

下一步可在[PCB 与 KiCad 工作流](pcb-kicad.md)里把模型假设转成布局、回流和测试点约束，或在[数值计算](numerical-computing.md)里进一步理解步长、残差和收敛。最有价值的 SPICE 产物不是一张波形图，而是一次可追踪的预测被验证、被修正或被否定。
