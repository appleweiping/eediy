# 版本控制与工程协作

Git 最有用的地方不是把文件送上云端，而是保留“这个设计为什么变成现在这样”。对 EE 项目而言，一次修改可能同时碰到原理图、器件值、仿真网表、固件、测量数据和报告。若提交历史只写 `update`，这些文件即使全都还在，也很难回答是哪项假设导致了结果变化。

先用本地仓库练习即可，不需要公开托管。Git 的官方[用户手册](https://git-scm.com/docs/user-manual)解释了 object、index、branch 和 remote；理解工作区、暂存区与提交的关系，比先背几十条命令更有帮助。

## 提交一项判断，而不是提交一个目录

从仓库里的 [RC 低通离线 starter](https://github.com/appleweiping/eediy/tree/main/examples/rc-lowpass)开始，先把它当成一个小型版本控制练习：参数文件、计算或仿真输入、结果生成脚本和说明已经分开。第一笔自己的提交只放可重建的基线：\(R\)、\(C\)、理论截止频率、运行命令和预期输出。生成的临时波形、缓存和本机路径不要混进来；Git 的 [`gitignore` 文档](https://git-scm.com/docs/gitignore)也特别说明，忽略规则不会让已经被追踪的文件自动消失，所以应在第一次提交前查看 `git status` 与暂存差异。

现在创建一条短分支，把电容改成原值的两倍。先在 issue 或设计记录中写下预测，再修改参数、重建结果并比较理论与仿真。把“更改参数”和“更新由参数产生的报告”分成两笔提交还是合成一笔，取决于每一笔是否能独立保持仓库可理解、可运行；关键不是追求最小行数，而是让审阅者能看见一个完整原因。

合并前逐行查看 diff。原理图旁若只出现一个无法解释的二进制变化，先导出可审阅的网表、BOM、ERC/DRC 报告或带版本号的 PDF。验证通过后创建带说明的 tag，并在另一个临时目录从该 tag 重建。只有 tag、参数、生成命令和摘要指向同一结果，它才是里程碑；一个名为 `final-final` 的文件夹不是。

## 分支用来隔离尚未成立的假设

分支最适合回答“如果换模型、拓扑或采样率会怎样”，不适合长期堆放互相依赖的半成品。每条实验分支写清问题和比较标准；结果不成立时可以不合并，但保留一段简短结论，避免几个月后重复同一失败。与远端协作时，先 `fetch` 再理解 remote-tracking branch 的位置，不要在不清楚差异的情况下把 `pull` 当同步按钮。

一次像样的自我评审至少能回答：

- 参数或接口到底改变了什么；
- 哪条测试、仿真或测量支持新结论；
- 生成物能否由源码和输入重建；
- 哪些风险、许可证或硬件假设随改动改变；
- 回退到上一提交后，系统行为是否真的恢复。

对固件与硬件的组合变更，合并成功不等于设备安全。重新核对引脚、供电、限流和默认输出，再进行烧录；来自陌生分支的脚本和固件应先阅读，不要直接在连接执行器或高能量负载的设备上运行。

## 二进制 EDA 文件和实验数据要另作选择

文本代码、网表和配置适合普通 Git diff；PCB 数据库、示波器捕获和长时间序列常常不适合。先问文件能否重建：能重建的输出通常不提交，只保存生成命令和摘要；不能重建的原始测量则保存校验和、来源和只读归档，但未必放在源码仓库。

[Git LFS](https://git-lfs.com/)把大文件内容放在外部存储，仓库中留下 pointer。它解决 clone 体积，不会自动提供有意义的波形或原理图差异，也依赖远端的容量、带宽和保留策略。若使用 LFS，要在贡献说明中写明所需客户端和取回数据的方法，并验证新克隆得到的是实际对象而非 pointer 文本。团队无法稳定访问同一 LFS 服务时，带校验和的发布归档或机构数据仓库可能更合适。

对于 KiCad 等可文本化的 EDA 格式，仍要避免两个人同时大范围重排版图或自动格式化文件。提交前生成 ERC/DRC、BOM 和关键截图用于评审，但权威源仍是原工程；截图只能说明当时看见了什么，不能替代可重新运行的设计检查。

## 误提交密钥时，先撤销密钥

`.gitignore` 不是保密工具，已经提交的 token 仍留在历史和其他 clone 中。若凭据进入仓库，第一步是撤销或轮换，而不是只删除最新文件。GitHub 的官方[敏感数据清理说明](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)列出了历史重写会改变提交哈希、影响 PR、签名、分支保护和其他协作者 clone 等后果；只有在明确协调并保留备份后才执行。

完成练习时，应有一段能读懂的基线历史、一条有预测的实验分支、一个可重建 tag，以及一次故意失败的验证。另一位读者从 clone 开始，不需要知道你电脑上的绝对路径，就能得到同一截止频率与差异说明。若他只能看到最终报告，却无法找到输入和生成命令，这个仓库仍然只是文件柜。

下一步可用[可复现工程](reproducibility.md)把重建命令接入自动检查，或用[技术写作](technical-writing.md)把分支里的取舍整理成设计评审。仓库中不要包含访问令牌、私人密钥、个人身份数据、受限器件资料或未经许可的课程答案。
