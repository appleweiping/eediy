# 实践指南

课程讲概念，项目常常卡在概念之间的接缝：构建环境换了，模型与实物对不上，探头改变了电路，或者原始数据已经找不到。这里不另排一套课表；按眼前的问题选一页即可。

## 按问题找入口

| 眼前的问题 | 先看 | 做完应留下什么 |
| --- | --- | --- |
| 不知道该选哪个软件、许可证或替代工具 | [工具与环境](tools.md) | 一项真实任务、淘汰条件和可重跑的小测试 |
| Notebook 只在自己的电脑上运行 | [Python 与 Jupyter](python-jupyter.md) | 带单位、依赖和失败用例的命令行入口 |
| C 项目换机器或换目标就出错 | [C 与 CMake](c-cmake.md) | 主机测试、目标构建和实际编译命令 |
| 改动、报告和数据版本对不上 | [版本控制](version-control.md) | 能从标记提交重建的基线与差异说明 |
| 数值结果随步长、容差或算法漂移 | [数值计算](numerical-computing.md) | 解析基准、收敛表、残差和重建命令 |
| SPICE 波形有了，却不知道模型是否可信 | [SPICE 电路仿真](spice-simulation.md) | 手算预测、工作点/AC/瞬态结果与模型限制 |
| 实测与预测不一致 | [仪器与测量](instrumentation-measurement.md) | 接线、探头设置、原始值和不确定度说明 |
| 原始数据、校准或处理步骤无法追溯 | [数据与实验记录](data-lab-notebooks.md) | 不覆盖的原始层、运行标识和处理链 |
| 换一台机器就生成不出同一结果 | [可复现工程](reproducibility.md) | 从空目录运行的命令和比较规则 |
| RTL 只在一张波形或一次上板演示中成功 | [HDL、仿真与 FPGA](hdl-fpga.md) | 自检查测试、反例、约束和时序/CDC 结论 |
| 固件能烧录，却无法解释启动或失联故障 | [嵌入式工具链](embedded-toolchains.md) | ELF/映射、日志、引脚观测和恢复路径 |
| 电路准备进入原理图、布局或制造 | [PCB 与 KiCad](pcb-kicad.md) | 源工程、规则、制造包和受限电流上电计划 |
| 不确定当前实验能否在现有条件下进行 | [实验安全](safety.md) | 风险边界、停止条件和合格设施需求 |
| 资料很多，却无法形成工程判断 | [文献检索](literature-research.md) | 可重放检索式、证据矩阵和未决测试 |
| 结论只能靠作者口头解释 | [技术写作](technical-writing.md) | 能追到条件、数据、版本和图表的短报告 |
| 多个任务已经互相依赖 | [项目实践](projects.md) | 规格、非目标、模型、验收和失败记录 |

一条常见的实验链是：先做解析预测，再用仿真检查模型，设计测量方法，保存原始数据，最后重建图表与结论。纯软件、FPGA 或文献项目会走另一条链；入口由当前故障决定。

!!! danger "硬件边界先于工具选择"
    市电、高压、较大储能、激光、射频功率、旋转机械、真空、高温和化学工艺需要相应设施、设备与监督。条件不够时，停在解析、仿真、公开数据或经过确认的低能量平台。

完成一次真实任务后，可以通过对应页下方的反馈入口补充版本变化、失败模式或替代路径。写清环境、输入和现象，比一句“这个工具不好用”更能帮助下一位读者。
