## 6.100L Spreads the Same Concepts Across a Semester; It Does Not Remove Half

MIT's Fall 2022 edition, taught by Ana Bell, is for students with little to no
programming experience and uses Python 3. The official
[syllabus](https://ocw.mit.edu/courses/6-100l-introduction-to-cs-and-programming-using-python-fall-2022/pages/syllabus/)
explicitly calls it the full-semester version of 6.100A (formerly 6.0001):
the material is the same, the pace is slower, and students who have never
programmed receive more practice time. It has no prerequisite; the original
class met for 2 lectures of 1.5 hours each week. Choose it when repeated
writing, execution, traceback reading, and correction are needed—not because
“slow” means less content.

The endpoint is to decompose a problem into precise steps, write small
programs, and understand the role of computation. It does not directly teach
embedded registers, instrument communication, real-time execution,
concurrency, numerical stability, or large-system architecture. For EE it
supplies the language layer of automation: variables and control flow,
function specifications, mutable data, testing, exceptions, classes,
complexity, and library use. Hardware interfaces and numerical methods belong
in later work.

Then perform three EEDIY routing diagnostics; they are not official MIT

1. Without copying lecture code, write a small program with input, a branch,
   and a loop, defining expected behavior for zero, a negative number, and an

2. Hand-trace `a=[1,2]; b=a; c=a[:]`, then separately modify `b` and `c` and

3. Implement a function from only its docstring, writing normal, boundary,
   and invalid cases before running tests. If tests cover only the examples,
   prioritize debugging, exceptions, and assertions.

Compress the first half only if all three can be explained and rerun in a
clean environment. Familiarity with one Python framework does not justify
skipping mutation and specification.

## Group Twenty-Six Lectures by How Programs Fail

The official calendar
spans 15 weeks and 26 lectures. Lectures 1–6 cover objects/types, bindings,
I/O, branches, loops, guess-and-check, bisection, and floats. Lectures 7–13
add functions, scope, tuples/lists, mutation/aliasing, testing/debugging,
exceptions, and assertions. Lectures 14–20 cover dictionaries, recursion,
classes, dunder methods, and inheritance. Lectures 21–24 analyze timing,
Big-Oh/Big-Theta, search, and sort. Lectures 25–26 close with a visualization
library, memory, hashing, simulation, and review.

Order work by failure mode, not video completion. In the first block, check
that control flow terminates. In the second, check function contracts and
unexpected mutation. In the third, check recursive base cases and class
invariants. In the fourth, define input size before discussing complexity.
In the fifth, check third-party library data, shape, range, and output files.
For lectures with a finger exercise, attempt it before running lecture code;
Lectures 21 and 24–26 instead begin with the lecture code. Then change exactly
one condition to cause and explain a traceback. Understanding a demonstration
is not the same as writing a program from a specification.

In an EE setting, those failures map to instrument scripts: an infinite loop
can stall acquisition, aliasing can corrupt a raw buffer, a bad exception can
hide over-range data, and an undefined input size can make a batch sweep
unbounded. These are analogies for applying the concepts; they are not course
labs. 6.100L supplies no physical
instrument lab; use only synthetic or public files and connect no hardware.

## Three Public Feedback Layers Have Different Visibility

The first layer is strongest for independent study. Official
[Finger Exercises](https://ocw.mit.edu/courses/6-100l-introduction-to-cs-and-programming-using-python-fall-2022/pages/finger-exercises/)
give short tasks by lecture and link solutions for Lectures 1–20 and 22–23.
Lecture 21 has no finger exercise, and neither do Lectures 24–26. Attempt each
exercise without consulting the solution, use a separate file, add self-tests,
then compare control flow,
return/mutation, and edge cases with the published solution.

The second layer is the official
[Problem Sets](https://ocw.mit.edu/courses/6-100l-introduction-to-cs-and-programming-using-python-fall-2022/lists/problem-sets/),
which publishes prompts and code bundles for PS0–PS5. PS0 is ungraded.
PS1–PS5 grow from compound interest/bisection into longer programs; PS5 uses
PIL for color-vision filters and steganography. Prompts provide manual cases
or student testers, but PS1 says its tester covers only part of the official
grader, and PS5 originally split grading 50% autograder and 50% manual image
inspection. The public problem-set index has no solution downloads and does
not expose the former hidden grader or manual review to off-campus learners.
Starter code and a tester are not a complete answer.

The third layer is original-class assessment. The syllabus weights problem
sets, mandatory finger exercises, and microquizzes at 45%, 10%, and 45%,
using the best 7 of 10 microquizzes; the calendar marks their timing and
topics. The public OCW materials reviewed here include neither microquiz papers
nor access to the course grading system. For self-study, replace them with timed exercises of your own:
small programs with preserved stdout, tracebacks, and tests, followed by peer
review against the specification. Do not memorize published solutions before
testing yourself or claim an MIT score.

## Spyder Is Historical Packaging; Files, Tests, and Semantics Define Delivery

These materials were published with the Fall 2022 course but reuse files from
several years. PS1 uses the same starter as 6.100A, `put_in_function.py` dates
to 2017, and the PS0 and PS5 bundles contain older files. A current environment
may replace the editor, but it must not silently rewrite the task.

For PS1, edit only `ps1a.py`, `ps1b.py`, and `ps1c.py`. Keep them in one
directory with the unmodified `ps1_tester.py` and `put_in_function.py`, and
preserve the comment anchors and variable names used by the conversion script.
Running the tester creates `ps1a_in_function.py`, `ps1b_in_function.py`, and
`ps1c_in_function.py`; these are generated intermediates, not submissions or
compatibility patches. Its 8 public cases are only a subset of the official
grader and do not cover every input location, output format, comment, or style
requirement.

For PS5, install the Pillow package, which imports through the `PIL` namespace.
Fill only the designated `pass` blocks in `ps5.py`; keep the tester, `.obj`
fixtures, input images, and font unchanged. `test_ps5_student.py` checks
`extract_end_bits` and 2 hidden images but not the color-vision filter. After
the student tester passes, inspect the filter and the 3 images used for manual
grading separately. If an API, path, or image format fails, preserve the
original error, minimal reproduction, version lock, and compatibility patch.
Do not fetch binary packages from an unknown mirror merely to imitate an old
setup. The syllabus identifies Guttag's third edition through MIT Press and
links code and errata.

A suitable **EEDIY supplement, not an official MIT assignment**, is a
waveform-quality reporter. Read a synthetic CSV from the repository without
modifying it; check
sample interval, empty rows, non-numeric and out-of-range values; emit
min/max/mean, threshold crossings, and a machine-readable summary. Test
normal, boundary, and invalid input and preserve one failing test that
deliberately aliases a buffer. Submit source, tests, samples, dependency lock,
raw output, and one rerun command. Filters, FFTs, and hardware acquisition
not taught in the course are not default requirements.

## Separate the Compressed Route from the Completion Route

The Fall 2016 [6.0001 syllabus](https://ocw.mit.edu/courses/6-0001-introduction-to-computer-science-and-programming-in-python-fall-2016/pages/syllabus/)
describes a half-semester course with 12 sessions, Python 3.5, 6 problem
sets, and 2 quizzes, and explicitly says quizzes and finger exercises are
unavailable on OCW. The separate official
[Assignments page](https://ocw.mit.edu/courses/6-0001-introduction-to-computer-science-and-programming-in-python-fall-2016/pages/assignments/)
says that assignment solutions are unavailable. 6.100L spreads
related concepts across 26 lectures, with solutions organized by lecture for
Lectures 1–20 and 22–23.
Choose 6.100L as a complete novice or after failing the mutation/testing
diagnostics. Use a 6.100A/6.0001-style compressed pace only after independently
implementing all three diagnostics from specifications and explaining edge
cases. Do not install Python 3.5 merely because the older course used it.

Auditable completion evidence contains a PS0 environment record; for every
lecture with a finger exercise, the first draft, self-test results, and a
short comparison with the published solution; source, public-tester output,
and additional edge tests
for PS1–PS5; timed drafts for the best 7 of 10 self-authored microquizzes,
clearly not MIT microquizzes; and the EEDIY reporter. This is an R0 review of
public materials and makes no first-hand completion claim. Feedback should
include lecture/PS, OS and Python/package versions, full traceback, minimal
input, and whether the starter file changed, so environment, prompt, and
implementation failures remain distinct.
