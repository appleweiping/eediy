### 6.004 course materials

MIT OCW publishes two 6.004 offerings with different strengths. Choose [Spring 2017](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2017/) for the first explanation: its 21 topic units move from digital abstraction, CMOS, and combinational and sequential logic through the Beta, caches, pipelines, virtual memory, interrupts, and concurrency. Most units include annotated slides, topic videos, and worksheets. Its syllabus names 7 labs and a final design project, but those lab files are not in the public navigation.

The [Spring 2009 syllabus](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2009/pages/syllabus/) corresponds to 8 public labs, an optional project, and 5 quizzes. A sound independent route therefore uses 2017 teaching with 2009 labs and problems, while labeling every note, program, and exam by year. It is not a “complete edition” that MIT ever taught as one term.

### Run the old tools only in isolation

The 2009 [Tools](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2009/pages/tools/) page provides JSim, BSim, TMSim, and Beta support files while referring to an old Sun J2SE. If a current runtime fails, use the old JRE only in a network-disabled, non-administrator VM with no writable host mount. Write down file hashes, OS, runtime, and launch arguments. Every lab is simulated; there is no “Beta development board” to buy.

Logisim, Verilog, or RISC-V can support a modern port, but they do not constitute the original lab. First obtain a saved result for an original input in JSim or BSim, then compare a modern implementation with the same test vectors. That separates tool semantics from design faults.

The community-maintained
[compstruct-vscode](https://github.com/jamestiotio/compstruct-vscode) extension
is MIT-licensed and adds language support plus JSim/BSim launch commands for
`.jsim`, `.tmsim`, and `.bsim` files. It is neither an MIT tool distribution
nor a source of lab answers. Use it to reduce editor friction, but keep the
original JAR and command line available. Launch the same input both ways; if
the outputs differ, inspect the working directory, classpath, and runtime.

### Labs and projects

The [2009 Labs](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2009/pages/labs/) use Labs 1–3 for CMOS, an adder, and an ALU; Labs 4–6 for a Turing machine, assembly, and the Beta; and Labs 7–8 for a trap handler and Tiny OS. For each lab, compare a truth table or instruction trace and timing assumptions with the official test, then inject one fault and explain the state change before and after the fix. For the Beta, test reset, both branch outcomes, load/store boundaries, interrupts, and illegal instructions. A screenshot saying “program ran” is not an architecture explanation.

Maintain one machine contract from the ALU through Tiny OS: which registers and memory each instruction reads and writes, how the PC changes on ordinary, branch, and trap paths, and where combinational paths meet register boundaries. For a short program, keep assembly, encoded words, a cycle-by-cycle PC and register trace, and expected memory state. After adding interrupts, reuse that program to test save, restore, and return. A mismatch in architectural state should be localized to instruction semantics or timing before inspecting the application.

Connect the 2017 cache, pipeline, and virtual-memory teaching to the same contract. For one miss, stall, or exception, state whether software-visible state changes, in which cycle an instruction may commit, and whether a failed request is replayed. A current HDL port then has a bit-level oracle instead of relying on a waveform that merely resembles a processor.

For a state problem much smaller than a complete Beta, the [synchronous FIFO exercise (not an official MIT lab)](https://github.com/appleweiping/eediy/tree/main/examples/sync-fifo) makes an ambiguous interface contract visible through empty, full, wraparound, and backpressure behavior. It does not replace JSim, BSim, or the Beta; it is only a runnable HDL instance of the state contract above.

The residential course also used staff interviews and live checkoffs. An off-campus learner cannot reproduce them. After each lab, explain the interface, key state, worst timing path, and one failing test without looking at the code. That creates more useful pressure than decorative screenshots.

### Problems expose a simulator-only understanding

The [Tutorial Problems](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2009/pages/tutorial-problems/) are grouped around 5 quizzes and have solutions. The [Exams](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2009/pages/exams/) page contains questions and answers for Quizzes 1, 2, 3, and 5; Quiz 4 has an answer but no question paper, so it cannot support a fabricated five-quiz average. Attempt each tutorial before opening its solution, then take the gradable historical papers under time limits.

A Beta implementation that rebuilds from a cold start best represents the course: the environment, 8 labs, vectors, traces, fault log, and 4 gradable quizzes should explain one another. If an ALU or unpipelined Beta submodule is later ported to a current HDL, compare identical vectors bit for bit and label it as a migration exercise, not a new MIT assignment.
