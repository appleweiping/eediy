## Treat the 2011 Course as a Design Course, Not an Installation Guide

MIT says on the
[6.01SC course home](https://ocw.mit.edu/courses/6-01sc-introduction-to-electrical-engineering-and-computer-science-i-spring-2011/)
that the OCW Scholar edition was designed for independent study. “Complete”
has a precise meaning here: course notes, lecture and recitation videos,
software and design labs, homework, nano-quizzes, and historical exams remain.
The people, robot bench, and automatic feedback from the enrolled course do
not. According to the
[syllabus](https://ocw.mit.edu/courses/6-01sc-introduction-to-electrical-engineering-and-computer-science-i-spring-2011/pages/syllabus/),
lectures were recorded in Spring 2011, while most software labs, design labs,
additional exercises, and homework came from Fall 2011. The public edition
also omits the Online Tutor, so PDF tutor questions receive no automatic
grading and many lab or homework questions have no solutions. This is an
archive boundary, not a missing download button.

There is no formal prerequisite, and 8.02 Electricity and Magnetism is listed
as a co-requisite. The following is only an EEDIY self-check for choosing what
to review, not an MIT admission or grading threshold: try writing a tested
Python class, calculating the first steps of a first-order difference
equation, writing KCL for a three-node circuit, and updating a discrete
distribution with Bayes rule. Review the minimum background behind whichever
attempt stalls, then sample the first two sections of Unit 1 again. Do not turn
the four prompts into one pass/fail score; they distinguish a conceptual gap
from a failure caused by old tools.

The [Resource Index](https://ocw.mit.edu/courses/6-01sc-introduction-to-electrical-engineering-and-computer-science-i-spring-2011/pages/resource-index/)

| Unit | Official problem and material | First work on a modern computer | What remains missing without a Pioneer |
| --- | --- | --- | --- |
| Unit 1 · Software engineering | Python objects, procedures, state machines, and combinators; notes, videos, software labs, and exercises | Rebuild small interfaces in Python 3; test primitives and combinators on fixed input sequences | The old `soar`/Tutor interaction and immediate classroom questioning |

| Unit 3 · Circuits | KCL, op-amps, Thevenin/Norton, superposition, and a light-seeking sensor head | Write node equations, then compare equivalent circuits and light changes in a low-voltage SPICE model | Circuits Maximus, a real light sensor, wiring, and component spread |
| Unit 4 · Probability and planning | Bayesian state estimation, search, maps, and paths | Compare a seeded hallway localizer, uniform-cost search, and A* on a fixed map | Sonar mapping, head/body coordination, and physical motion error |

The working rhythm need not be identical in every unit. Unit 1 suits “read the
interface, write a small example, attempt the exercise, add tests.” Unit 2
needs hand-derived and numerical responses side by side. Unit 3 starts with a
node-labelled schematic before equations. Unit 4 keeps random seeds and failed
cases. This preserves the course’s four encounters with abstraction without
mistaking “launch old robot software” for the educational objective.

## A Unit 3 KCL Check Must Say What “Small” Means

For a nodal-admittance equation \(Gv=i\), EEDIY recommends reporting the
dimensionless residual

\[
\rho_{\mathrm{KCL}}=
\frac{\lVert Gv-i\rVert_\infty}
{\max(\lVert Gv\rVert_\infty+\lVert i\rVert_\infty,\ I_{\mathrm{floor}})}.
\]

For a purely numerical example, set
\(I_{\mathrm{floor}}=10^{-12}\,\mathrm{A}\) in the test so a zero-excitation
case does not produce a meaningless denominator. For EEDIY-built, well-scaled
float64 regression examples with \(\kappa_\infty(G)\le 10^6\),
\(\rho_{\mathrm{KCL}}\le 10^{-9}\) can conservatively serve as an
editor-selected alarm line. It is intentionally far above float64 machine
precision, \(2.22\times10^{-16}\), to accommodate differences in scaling,
implementation, and solver path. The condition number here only flags cases
that need separate sensitivity analysis. \(10^{-9}\) is neither a
backward-residual theorem derived from \(\kappa\epsilon\) nor a hardware
accuracy specification.

For an ill-conditioned matrix or \(G\) and \(i\) formed from measured
components, report the dimensionless residual, absolute KCL imbalance in
amperes, and condition number separately. The residual checks how well the
computed solution satisfies the equations; the condition number instead
supports forward-sensitivity analysis under input perturbations. Add
component, instrument, and model uncertainty when comparing measurements, but
do not insert \(\kappa\epsilon\) directly into the residual threshold. This is
an EEDIY calculation check, not an MIT laboratory threshold.
Analytic-versus-numerical error in Unit 2 and localization error in Unit 4 need
the same explicit units, input domain, and reason for the chosen tolerance.

## Keep Python 2.6 and the Pioneer in Historical Reproduction

The official [Software and Tools](https://ocw.mit.edu/courses/6-01sc-introduction-to-electrical-engineering-and-computer-science-i-spring-2011/pages/software-and-tools/)
page requires Python 2.6.x. MIT tested 2.6.6 and expected 2.6.7 to work. The
stack includes IDLE, `lib601`, the `soar` simulator, and period-specific
instructions for GNU/Linux, Windows 7/XP, and the then-current Mac OS X.
Physical design labs used an ActivMedia Pioneer 3-DX and Circuits Maximus. The
same page says most design-lab content can be covered without the robot, but
sonar mapping, head/body coordination, and simulation-to-physical differences
cannot.

For implementation history, put the download and Python 2.6 in an offline,
isolated, disposable VM and record the operating system, interpreter, and file
checksums. Do not make an unmaintained interpreter a daily networked
environment. Work with Python 3, a current mobile platform, or different
sensors should be labelled “EEDIY adaptation” and define new coordinates,
sample period, noise, actuator saturation, and safe-stop behavior. A Pioneer
3-DX is not a present-day course kit to buy, and the archive supplies no
current replacement BOM or price. Optional circuits stay isolated,
low-voltage, and current-limited; clear the test area and provide a physical
stop before a mobile platform first moves.

## Rebuild Useful Checks after the Online Tutor

The enrolled pattern was 1 lecture of 1.5 hours, 1 software lab of 1.5 hours,
and 1 design lab of 3 hours each week. Immediate software-lab feedback and
partners or staff interviews in design lab cannot be recovered automatically
from PDFs. Use each public resource differently: answer a nano-quiz before its
published solution; check the 4 written homework sets and unsolved tutor/lab
questions with unit tests, dimensions, extreme inputs, and peer explanation;
complete the 2 midterms and final closed-book before reading solutions.

The official [Final Exam](https://ocw.mit.edu/courses/6-01sc-introduction-to-electrical-engineering-and-computer-science-i-spring-2011/pages/final-exam/)
page says the final is cumulative with greater weight on Unit 4 and preserves
papers and solutions from several terms. Keep the first script, classify
errors as concept, model, calculation, or code, repeat the work one week later,
and give a 5-minute explanation of why the same abstraction idea appears in a
state machine, an op-amp, and a probability distribution. That is closer to
the original interview than copying a clean solution.

For one optional integration exercise, place a state-machine controller in a
virtual hallway. It reads a noisy light/distance model, moves through linear
control, localizes with Bayes, and plans a return with search. Make every layer
replaceable in isolation and document inputs where the model fails. This is an
EEDIY after-course exercise, not part of MIT 6.01SC. The reason to choose the
course is equally specific: it is not a current Python course, a complete
circuits course, or a modern robotics course. It is an introduction in which
software, dynamic systems, circuits, and uncertainty share the same design
judgment.
