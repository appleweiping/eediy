### Bits, Signals, and Packets Must Explain One Another

MIT [6.02 Fall 2012](https://ocw.mit.edu/courses/6-02-introduction-to-eecs-ii-digital-communication-systems-fall-2012/pages/syllabus/) uses 24 lectures for three layers. Lectures 1–7 cover compression and coding as Bits. Lectures 8–16 cover noise, BER, LTI channels, modulation, and synchronization as Signals. Lectures 17–24 cover sharing, queues, routing, and reliable transport as Packets. It suits learners with 18.03, 6.01, and enough Python to build small modules. The central work is a cross-layer explanation: how noise and ISI change decisions, how errors trigger retransmission, and how delay and queues finally limit throughput.

### Assignments and feedback

On [Assignments](https://ocw.mit.edu/courses/6-02-introduction-to-eecs-ii-digital-communication-systems-fall-2012/pages/assignments/), PS1–3 implement Huffman and LZW compression, linear block codes, and Viterbi decoding. PS4–6 treat signaling, clock recovery, noise, ISI, eye diagrams, and modulation. PS7–9 implement MAC, routing, and sliding windows. Give each module a hand-computable fixture and an independent oracle before scaling the simulation. Codewords, paths, and event traces should match exactly; floating-point comparisons should state sample rate, dtype, normalization, seed, and tolerance.

The course also has 11 solved [Tutorials](https://ocw.mit.edu/courses/6-02-introduction-to-eecs-ii-digital-communication-systems-fall-2012/pages/tutorials/), but no public official solutions to the 9 problem sets. Residential students had 6 TA checkoff interviews. Use tutorials to correct foundational work, keep quizzes and important PS modules blind, and ask a peer to change a noise level, link cost, or window and require a directional prediction before rerunning.

In the Bits block, trace one short message from reversible Huffman or LZW coding into the syndrome or path metric of a block or convolutional code. For a Viterbi decoder, preserve a tiny trellis, known received sequence, and step-by-step survivor table. Comparing only the final bit string conceals tie breaking, metric normalization, and termination differences. Keep the same event-level evidence in Packets: timestamp every queue event, route update, acknowledgment, and timeout and record its cause.

### Audiocom has verified provenance but an unstable environment

The [Audiocom ZIP](https://ocw.mit.edu/courses/6-02-introduction-to-eecs-ii-digital-communication-systems-fall-2012/resources/audiocom/) for PS4–6 is an MIT distribution, but 4 `.pyc` files have no public source and no reproducible build chain. The original stack used Python 2.7, wxPython 2.8, and old NumPy and Matplotlib. If an isolated VM can generate a reference trace for a fixed input, compare that trace with a Python 3 rewrite. If it cannot, reimplement from the public handout and state that behavioral equivalence is unverified.

Pass file loopback before enabling a real speaker and microphone. Fix the WAV, sample rate, amplitude limit, and seed and test transmitter, channel, synchronizer, and receiver separately. Audio hardware is an optional adapter; RF transmission is not required. On a new computer, replay the same WAV path first so algorithm and device changes are not mixed.

The Signals block is about how a decision point emerges from continuous samples. Save the transmit pulse, channel impulse response, matched-filter output, sampling phase, and constellation decision. Inject noise, ISI, and clock offset one at a time. Label an eye diagram's plotting window and normalization; give a BER curve its bit count and confidence interval. Feed retransmission overhead caused by those errors back into the packet queue and compare stronger coding, lower useful rate, and fewer retries. A receiver failure can then be assigned to timing, channel inversion, or detection, while its effect on delay and throughput remains visible.

### Use an Open Tool for Cross-Layer Synthesis

Mark Wickert's unofficial [scikit-dsp-comm](https://github.com/mwickert/scikit-dsp-comm) is BSD-2-Clause teaching software with modulation, synchronization, convolutional coding, filters, and example notebooks. It is neither 6.02 starter code nor an answer key. After completing the original interfaces, use it to check a current implementation of BER, pulse shaping, or synchronization.

The final exercise can compress a message, convolutionally encode it, pass it through a baseband channel with noise, ISI, and timing offset, recover a packet, and reroute after a link failure. Report BER, useful throughput, delay, and overhead, with each layer's inputs, outputs, units, and failure assumptions. Separate codec, eye, and routing demos do not satisfy 6.02 until their constraints on the next layer can be explained.

The point of 6.02 is cross-layer causality: extra redundancy changes airtime,
timing error becomes packet loss, and packet loss triggers routing behavior.
