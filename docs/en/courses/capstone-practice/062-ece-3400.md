### Course focus

Cornell [ECE 3400](https://ocw.ece.cornell.edu/courses/ece-3400-ece-practice-and-design) archives Spring 2016: 3 lectures each week, 4 labs in the first half, then a 7–9 person maze-mapping robot, with no exams. The [Syllabus](https://ocw.ece.cornell.edu/courses/ece-3400-ece-practice-and-design/ece-3400-syllabus) asks the robot to identify paths and walls, find a source beacon, and send a map to a base station; students also rotate leadership across 6 projects. Choose a shorter lab if you only want sensor wiring. Choose this course for interfaces, integration, and team decisions.

The assumed background includes basic analog/digital circuits, microcontroller programming, soldering and measurement, and state machines. Independent study cannot recreate the large team, but it can still teach how interfaces are negotiated, how design choices propagate, and how one module is handed to the next stage of integration.

### Labs and projects

[Projects and Labs](https://ocw.ece.cornell.edu/courses/ece-3400-ece-practice-and-design/ece-3400-projects-and-labs) publishes Lab 1–4 and the final brief, but no solutions. [Lab 1](https://ocw.ece.cornell.edu/files/2017/03/ece3400_lab1-1ll6xvm.pdf) develops instrumentation, wiring, and basic control; each later lab should retire a sensing, motion, communication, or integration risk. By [Lab 4](https://ocw.ece.cornell.edu/files/2017/03/ece3400_lab4-25e5n88.pdf), every module should support offline regression from a captured input or fixture.

The notebook is where daily engineering decisions happen. Date and version identify the system under test; schematic and probe point identify the signal; expectation and raw data decide what to change next. A team names an owner for each interface. A solo learner can revisit the same page a day later and look specifically for an assumption that was missed the first time.

### Start the final project with an interface table

The [Final Project brief](https://ocw.ece.cornell.edu/files/2017/03/ece3400_finalproject-2jk3dax.pdf) supplies the 2016 contest specification. Extract arena, wall/path, beacon, communication, scoring, and timing constraints before selecting the chassis, sensors, processor, and radio. The interface table should include power, logic levels, pinout, message fields, coordinate frames, units, update rate, timeout, and safe stop.

Integrate from manual stop and teleoperation through straight/turn motion, one sensor, local map, beacon, radio, and full autonomy, adding only one closed loop at a time. Repeat the final run under identical conditions and report success rate, map error, beacon false positive/negative, packet loss, and battery state.

### Integration testing

The public site lacks lecture notes, exams, lab solutions, equipment, team assignment, and in-person checkoff. Without a physical platform, use a simulator, sensor replay, map, and base-station mock while naming unvalidated dynamics, noise, and RF.

For independent study, put the lab notebook, dated interface version, BOM, source/schematics, raw telemetry, and repeated demonstration results in a shared workspace. When a decision actually changes the design, explain which data ruled out the alternative. Make ethics concrete too: decide when camera data are deleted, whether the radio band is permitted, how batteries are disposed of, and how a runaway robot stops. When an interface changes, rerun mapping and motion separately to see exactly where the effect propagates.
