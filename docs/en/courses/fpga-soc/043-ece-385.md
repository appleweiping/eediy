### Access and version notes

Use this map after small RTL blocks, for full FPGA integration; choose an
open-assignment course if you need prompts and a grader. Illinois's anonymous
material stops at the catalogue.
Its [ECE 385 department page](https://ece.illinois.edu/academics/courses/ece385)
and the university [course catalogue](https://catalog.illinois.edu/courses-of-instruction/ece/)
agree on the current spine: TTL, SystemVerilog, FPGA implementation, timing,
datapath/controller design, a microprocessor, software/hardware co-design, and
system-on-chip work. The prerequisites are ECE 110 and ECE 220. The
[Fall 2025 Course Explorer record](https://courses.illinois.edu/schedule/2025/fall/ECE/385)
confirms the term-specific course identity. The department page also names
Xilinx Vivado and laboratory instruments. Current assignments, starter files,
rubrics, and staff feedback are not public. These catalogue-scoped independent
exercises are not Illinois coursework.

Before starting, minimize a Boolean function, draw and encode an FSM,
distinguish setup/hold from metastability, write a self-checking SystemVerilog
testbench, and read a synthesis timing report. A
parameterized counter with a debounced input and seven-segment output is a
useful warm-up; define clock, reset, and I/O contracts before simulation,
synthesis, and pin constraints.

### Failure Modes Determine the Independent Project Sequence

Using the official topics as scope, begin with a combinational network whose
truth table is exhaustively checked. Then build a
switch synchronizer/debouncer and deliberately inject contact bounce so the
design has a falsifiable timing requirement. Follow with an FSM whose
illegal-state recovery is tested, an arithmetic datapath whose controller is
checked cycle by cycle, and a small processor or bus-connected peripheral.
Write the specification, fixture, and expected timing for each one before the
RTL.

Pair every block's contract and RTL with assertions, testbench, lint output,
synthesis utilization, timing reports, constraints, and one real failure at a
specific cycle. Use waveforms to find it and the testbench to judge it.
Reset during an active transaction, vary back-pressure where a handshake
exists, and make at least one test fail when an assertion is removed or the
latency is changed.

### Make Datapath, Control, and Clock Boundaries Explicit

Fix the address map, data width, clock domains, latency, byte enables,
valid/ready rules, and reset behavior before integration. Use a reference model
for arithmetic and instruction-visible state, then compare it with RTL at
committed transaction boundaries. CDC work should identify each crossing as a
single-bit level, pulse, reset, or multi-bit transfer; a two-flop synchronizer
is not a universal answer.

The implementation checkpoint names the exact Vivado version, FPGA part,
clock constraint, warning policy, seed, and command or Tcl script that creates
the project from source. If the chosen board differs from Illinois hardware,
put voltage, pinout, clock, memory, and peripheral differences in the interface
table. Behavioral simulation answers a functional question; timing closure and
safe electrical connection remain separate checks.

### The Independent SoC Project Maps Only to Published Topics

Choose one peripheral-rich result—VGA, audio, a soft CPU, or a memory-mapped
sensor. Add counters, status registers, and an embedded logic analyzer so a
failure can be located at its first bad cycle and interface. Without hardware,
stop at “pre-board complete” and include implementation reports; on hardware,
note the bitstream hash, board revision, rail and I/O-voltage checks, and
bring-up sequence.

The best exercise here is not merely making VGA or audio come alive, but
finding the first bad cycle across blocks: was it the latency contract, a clock
boundary, or board I/O? Compare area, latency, clock rate, and debug visibility
at the end. If a higher Fmax makes faults harder to locate, that trade-off is
itself a SoC-integration result.
