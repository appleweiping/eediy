### Course fit

MIT [6.1810 Fall 2023 on OCW](https://ocw.mit.edu/courses/6-1810-operating-system-engineering-fall-2023/)
and the semester's [PDOS site](https://pdos.csail.mit.edu/6.1810/2023/) together form an
internally consistent source set.
RISC-V xv6 is small enough to read yet contains processes, page tables, traps,
file systems, locks, and networking. `xv6-labs-2023` is the semester's lab
repository; `util`, `syscall`, `pgtbl`, and their peers are the per-lab
starting branches. The evolving `xv6-riscv` main branch is not their baseline.

The official [overview](https://pdos.csail.mit.edu/6.1810/2023/overview.html)
assumes C and systems experience. Be comfortable with pointers, structures,
function pointers, concurrent C, Unix shell use, Git, and basic virtual
memory, and be able to narrow a crash with a backtrace, address, and source.
Review enough RISC-V assembly to read a trap path before starting if needed.

### Interleave the Book, Source, and Labs

Do not read the [rev3 xv6 book fixed by the 2023 course site](https://pdos.csail.mit.edu/6.1810/2023/xv6/book-riscv-rev3.pdf)
apart from the code. After processes, trace `userinit` into the scheduler. After page
tables, translate a single virtual address. After traps, follow a user instruction
through the trampoline and kernel handler and back, recording the page table,
CPU mode, and relevant locks.

The [xv6-riscv repository](https://github.com/mit-pdos/xv6-riscv) is a source
reference, but assignments belong on the designated lab-repository branch.
At the start of a lab, record the commit at `origin/util`, `origin/syscall`, or
the branch named by that handout. Treat the course-hosted rev3 PDF, dated
2022-09-05, as the reading baseline and the recorded branch commit as the code
baseline; a repository name is not a universal lab commit. Before editing,
preserve `make qemu` and `make grade` results and note the compiler, QEMU, and
host OS.

The first [utilities lab](https://pdos.csail.mit.edu/6.1810/2023/labs/util.html)
implements `sleep`, `pingpong`, a concurrent prime sieve, `find`, and `xargs`;
the handout explicitly calls `origin/util` this lab's branch. System calls,
page tables, traps, copy-on-write, a network driver, locking, the file system,
and `mmap` likewise use branches named by their handouts. Start from that named
branch so the prompt, grader, and code stay aligned.

### Each Lab Centers on a Kernel Invariant

Run the focused handout tests and full `make grade`, then add a boundary
case such as an early pipe close, memory exhaustion, concurrent unlink, or a
copy spanning pages. State the page-reference, lock-order, or transaction
invariant before changing code. Afterwards, retain a minimal failure with
its trigger, panic or backtrace, root cause, and repair evidence. Public tests
cannot cover every concurrent and failure path, but this record explains why
the change should hold.

Follow dependencies: utilities and system calls; page tables and
copy-on-write; traps and alarm; sleep/wakeup and locking; then inodes, the log,
and buffer cache. A course index can connect every lab to a book chapter,
key source, tests, and a failure.

### Access and version notes

The public sites provide handouts, book, source, and local grading scripts,
not class meetings, TA feedback, hidden tests, or Gradescope scores. The local
grader is useful regression, not MIT certification. The toolchain uses
RISC-V GCC/binutils, GDB, and QEMU; pin versions in Linux or WSL so an update
does not resemble a kernel defect.

Finish with a real xv6 kernel fault: follow its call site, shared state,
error return, and release path to the cause, then rerun the added boundary test
on the Fall 2023 branch. xv6 is excellent for seeing an invariant break, but it
does not provide production hardening, recovery, or protection for sensitive
data.
