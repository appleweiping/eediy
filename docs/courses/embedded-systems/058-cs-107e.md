## 从机器码一直造到能交互的裸机系统

Stanford CS107E 是 CS107 的硬件/嵌入式变体：从 RISC-V 指令和机器码开始，逐层实现 C
运行环境、编译/链接/加载、内存管理和裸机外设，最终让一块没有操作系统托底的单板机
变成可交互的个人系统。当前公开站对应 Spring 2026；课程在 2024 年从 Raspberry Pi/ARM
迁移到 AllWinner D1 SoC 的 Mango Pi MQ-Pro。它不是 C 语言入门，也不是一组互不相关的
树莓派小项目。

[About](https://cs107e.github.io/about/) 把课程目标写成理解信息表示、程序执行、外设
控制，并熟练使用命令行开发工具和 C。先修是 CS106B 或同等水平：递归、指针、链表和树、
抽象数据类型、栈/队列/集合/映射、搜索、排序与哈希都应已经掌握。更直接的自测是：
能否在不靠 IDE 的情况下读懂一段含指针与动态结构的 C/C++ 代码，能否用 Git 恢复一次
错误修改，能否在纸上解释调用栈和 heap 的区别。三项都不稳时，CS107E 的硬件故障会和
C/工具链故障叠在一起，几乎无法定位。

## 七份作业是一套持续生长的系统

[Assignments](https://cs107e.github.io/assignments/) 先用 Assignment 0 完成 Git 与环境
准备，之后不是七个孤立项目，而是同一套裸机库的演化：

1. **Larson Scanner：**从 GPIO/MMIO 与 RISC-V 指令进入最小硬件控制；
2. **Clock：**建立计时、显示和模块边界；
3. **String Formatting：**写 UART/字符串基础设施，让系统能够报告自己的状态；
4. **Stack and Heap：**进入调用约定、内存布局和 allocator；
5. **Keyboard and Simple Shell：**接入 PS/2 键盘并形成命令交互；
6. **Graphics Library and Console：**操作 framebuffer，把文本和图形输出变成库；
7. **System Monitor with Interrupts：**用 GPIO interrupt、keyboard driver 与
   interrupt-safe 数据结构完成一个可交互 console。

A2–A7 持续扩充 `libmymango`，后续依赖前面的接口与实现。跳过一项不是少做一个项目，
而是让后面失去地基。官方历史口径是每份周作业 10–20 小时；这不是保证，但足以说明课程
不能和两三门重作业课程并行。

## Lab 先把难调的东西摊开

[Labs](https://cs107e.github.io/labs/) 列出 Lab 0–9，包括 Orientation、认识 Mango Pi、
Below C Level、Debugging and Testing、Linked and Loaded、Keyboard Surfin’、Drawing
into the Framebuffer、Mango Pi Interrupted，以及两次项目组会。正式课程中 lab 每周
两小时、两人合作、按参与计分，并为当周 assignment 做准备。

自己做时，可以照着 “prelab → guided exercise → check-in” 走：先写出硬件寄存器和
预期波形，再执行引导任务，最后解释观察到的状态、失败和修复。少了 staff reference
implementation 和现场伙伴，每个驱动都得自己留观察点：
UART 日志、GPIO 逻辑分析、最小测试程序和故障树。否则一块黑屏板无法告诉读者是链接
脚本、时钟、引脚、协议还是内存破坏。

## Final project 延续前七周，而不是另起炉灶

Final project 通常两人一组，用 2–3 周在本学期积累的库上构建硬件—软件系统。
[Project](https://cs107e.github.io/project/) 要求 proposal 同时写 core、stretch 和
fallback 目标，列出材料预算、分工、按风险排序的时间表与中点里程碑；最终交付是现场
demo、代码和 README。Rubric 看 Challenge/Technical Achievement、Execution 和
Originality/Artistry。课程没有考试，项目就是集成考核。

把项目给别人看时，至少带上 BOM 与接口图、core/stretch/fallback 三层范围、最难部分的
最小原型、里程碑记录、可重复构建说明、故障日志、demo 和 README。若使用外部或
AI 辅助代码，必须标示来源和本人贡献；正式作业政策允许 AI 做背景解释，但
assignment-specific 帮助需要引用，且禁止把自己的作业代码发送给 AI 或提交 AI 生成
代码。

## 先确认哪些材料拿得到

正式 Spring 2026 课程每周有两次 90 分钟 lecture 和一次两小时 lab，lecture 不录制，
没有远程/SCPD 版本，校内班限 40 人并需要问卷和 instructor consent。
[Stanford FAQ](https://web.stanford.edu/class/cs107e/) 写明学校提供含 SBC、面包板、
跳线、LED 和晶体管的套件；2025–26 标价 75 美元，SBC 学期结束回收。公开访客可以读
writeup、[Schedule](https://cs107e.github.io/schedule/) 和 guides，却不能访问在课学生
使用的课程 repo，也拿不到 staff reference implementation、正式 QA、Ed、现场 lab 与
完整套件。

## 先核对工具链，再买板

Assignments FAQ 仍残留一句 “cross-development tools for arm processors”，但 2026
首页、schedule、slides 与 About 均已明确使用 RISC-V；这句应视为迁移后的旧文案，
不能把当前课程写回 ARM。硬件、价格和回收政策也会随学期变化。

我的建议是先确认公开工具链是否能在自己的系统上运行，并接受 starter/reference code
的缺口，再决定要不要买 Mango Pi。
公开 writeup 足够看懂课程怎样长成，但没有课程 repo、QA 和现场套件时，你做的是一条
尽量忠实的公开复建路线，不是 Stanford 在课体验的复制品。
