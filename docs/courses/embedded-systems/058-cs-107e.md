### 从机器码做到裸机交互系统

已经会 C、又想亲手建立 runtime、allocator 和 interrupt library，Stanford [CS107E](https://cs107e.github.io/about/) 很适合；第一次学指针的人应先选普通系统编程课。课程从 RISC-V 指令、C 运行环境和链接加载一路做到内存、外设、中断与个人系统。Spring 2026 使用 AllWinner D1 的 Mango Pi MQ-Pro；课程在 2024 年从 Raspberry Pi/ARM 迁移而来，旧工具说明不能当作当前目标。

### 作业与反馈

[Assignments](https://cs107e.github.io/assignments/) 从 Assignment 0 的环境配置开始，随后依次完成 Larson Scanner、Clock、String Formatting、Stack and Heap、Keyboard and Simple Shell、Graphics Library and Console、System Monitor with Interrupts。A2–A7 持续扩展同一个库，跳过前项会直接破坏后项接口；历史工作量为每周约 10–20 小时。

新增一层时先回测旧层：GPIO 与 timer 看 logic trace，formatting 与 allocator 跑
host-side/unit tests，keyboard 与 shell 对 raw scan code 和 parser case，framebuffer 核对
像素坐标与边界图，interrupt monitor 则检查 interrupt count、latency 与 shared-state
invariant。遇到 memory corruption，先缩成最小触发程序并画出地址图；最终画面不能解释底层错误。

课程组织维护的 [xfel](https://github.com/cs107e/xfel) 是当前 D1 bring-up
所用工具的 MIT-license fork，README 公开 memory read/write、hexdump、execute 与 JTAG
入口。仓库只承担工具链，不提供 assignment implementation。Assignment 0 先读出 chip
version，再从已知安全地址回读，并核对镜像 checksum；不明 flash 区域不要试写。

[Labs](https://cs107e.github.io/labs/) 的 Lab 0–9 从板卡与低于 C 的执行细节，走到调试、
链接、键盘、framebuffer 和 interrupt，并含 2 次项目组会。每个 driver 配一个最小测试，再用
UART 日志或 GPIO trace 观察它；黑屏本身无法区分链接脚本、时钟、引脚协议和内存破坏。

课程的核心接口是你亲自建立的 runtime。链接脚本中标出 text/data/bss/heap/stack 边界，allocator 写出 alignment 与 exhaustion 行为，interrupt handler 明确保存/恢复上下文和可重入限制。每加入一个外设，保留轮询版的小基线，再切到 interrupt-driven 版本；两者对照能把 protocol 错误与 concurrency 错误分开。

### 结课项目

[Project](https://cs107e.github.io/project/) 通常由 2 人用 2–3 周完成，proposal 同时给
core、stretch、fallback、预算、分工和风险里程碑。校外可单人做，但仍沿用自己的 allocator、
console、interrupt 和驱动；换用现成 OS 会割断前 7 周的系统主线。项目目录里放 BOM、接口图、
构建命令、故障日志、现场或录制 demo，以及解释最难取舍的 README。

### 访问与版本说明

Spring 2026 每周有 2 次 90 分钟 lecture 和 1 次 2 小时 lab，不提供录像或远程版本，班级上限 40 人。[Stanford FAQ](https://web.stanford.edu/class/cs107e/) 所列 2025–26 kit 为 75 美元，且 SBC 期末回收。访客能读 [Schedule](https://cs107e.github.io/schedule/) 和公开 writeup，却拿不到学生 repo、reference implementation、Ed 和现场 check-in。

购板前先确认公开工具链能跑，也确认确实买得到 Mango Pi。CS107E 的关键不是外设数量，而是
机器码、runtime、allocator、driver 与 interrupt-driven console 是否沿着同一条 boot path
接起来；几份彼此无关的 peripheral demo 看不出系统如何逐层长成。

最值得做的演示从断电开始：构建镜像、启动，通过 UART 或 console 运行诊断命令，再触发一次
可恢复错误。README 画出 boot path、memory map、driver dependencies 与项目复用关系。若
错误恢复仍依赖自己写的 runtime 和 interrupt library，这个项目才真正接上 A2–A7 的主线。
