## 实践闭环

### 《Secure Hardware Design · MIT 6.5950》可审计硬件威胁模型与防护实验

这是维护者为《Secure Hardware Design · MIT 6.5950》建议的自学项目，不是课程官方作业。为硬件安全在自建 RTL 模型上定义授权威胁，模拟时序侧信道或故障并评估恒定时间/冗余防护，不攻击第三方设备。

**来源：** 维护者建议项目

**交付物**

- 资产、攻击者能力、信任边界、授权范围与不可接受影响的威胁模型
- 自建 RTL/软件模型、攻击仿真、基线和防护实现源文件
- 至少 1000 条基线/攻击/防护轨迹及泄漏或故障成功率原始数据
- 一份防御报告，比较安全收益、面积/延迟代价和残余风险

**验收**

- 基线攻击在合成数据上显著优于随机猜测，报告置信区间而非只报单次结果
- 防护后攻击优势下降至少 80%，或解释未达标原因和剩余泄漏
- 覆盖全零/全一秘密、重复输入、复位期间和故障未触发边界
- 用第二个统计检验或独立故障检查器交叉核对结论

**复现要求**

- 提交自建模型、攻击/防护代码、测试、威胁模型和 README
- 固定工具版本、综合参数、种子和全部实验配置
- 保存去敏后的合成原始轨迹、校验和与自动生成报告

**安全边界：** 仅仿真 — 仅测试自己创建且明确授权的仿真模型；不得提供针对第三方设备的利用流程、真实密钥或绕过访问控制的操作。
