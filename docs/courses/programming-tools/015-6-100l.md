## 6.100L 把同一批概念摊开一学期，不是删掉一半

MIT 的 Fall 2022 版本由 Ana Bell 主讲，面向 little to no programming experience，使用
Python 3。
官方 [Syllabus](https://ocw.mit.edu/courses/6-100l-introduction-to-cs-and-programming-using-python-fall-2022/pages/syllabus/)
明写它是 6.100A（原 6.0001）的 full-semester version：材料相同，速度放慢，给从未编程的
学生更多练习时间；无先修，原班每周 2 次、每次 1.5 小时 lecture。选择它的理由应是需要
反复写、跑、读错和订正，而不是把“慢”误解成内容更少。

课程目标止于能把问题拆成明确步骤，写出小型程序并理解 computation 的作用。它不会直接
教嵌入式寄存器、仪器通信、real-time、并发、数值稳定性或大型软件架构。对 EE，它提供的是
自动化脚本的语言层：变量与控制流、function specification、mutable data、testing、
exception、class、complexity 和 library use；硬件接口与数值方法要在后续课单独学习。

作出的版本裁决。先原样运行 `pkgtest.py` 做上述有限 smoke test，再按直接 PDF 自建并

不同文件里的 3.0+、3.5+、3.9 和 Spyder 5.2.2 都只是历史陈述，不是今天的兼容保证；
任何兼容修改都单独提交 diff。

随后做三项 EEDIY 分流诊断，它们不是 MIT 官方考试：

1. 不复制 lecture code，写一个带 input、branch 和 loop 的小程序，并为零、负数、空字符串
   设计预期行为；若只能在 IDE 里逐行试到“能跑”，留在 6.100L 的前 6 讲。
2. 手工追踪 `a=[1,2]; b=a; c=a[:]` 后分别修改 `b` 与 `c` 的结果，并解释 alias 与 clone；
   若对象身份和值相等混在一起，不要跳过 Lectures 9–13。
3. 只根据 docstring 实现一个函数，先写 normal、boundary 与 invalid case，再跑测试；
   若测试只覆盖示例输入，优先完成 debugging、exceptions 与 assertions。

三项都能解释且能在干净环境重跑，才考虑压缩前半段；只会某个 Python framework 但说不清
mutation 和 specification，仍不适合跳过。

## 二十六讲按“程序怎样坏掉”分成五次升级

官方 Calendar
横跨 15 周、26 次 lecture。Lectures 1–6 处理 object/type、binding、I/O、branch、loop、
guess-and-check、bisection 与 float；Lectures 7–13 进入 function、scope、tuple/list、
mutation/alias、testing/debugging、exception/assertion；Lectures 14–20 处理 dictionary、
recursion、class、dunder method 与 inheritance；Lectures 21–24 分析 timing、Big-Oh/
Big-Theta、search 与 sort；Lectures 25–26 以 visualization library、memory、hashing、
simulation 和 wrap-up 收尾。

学习顺序应围绕失败模式，而不是视频编号打卡。第一段检查控制流是否终止；第二段检查
function contract 和对象是否被意外修改；第三段检查递归 base case 与 class invariant；
第四段先定义 input size 再讨论 complexity；第五段检查第三方 library 的数据、shape、
range 与 output file。有 finger exercise 的讲次先盲做；Lecture 21、24–26 则从 lecture
code 开始。随后只改一个条件制造失败并解释 traceback。看懂演示不等于能从
specification 生成程序。

在 EE 场景里，可把这些失败模式对应到仪器脚本：无限 loop 会卡住采集流程，alias 会污染
原始 buffer，错误 exception 会吞掉超量程数据，未声明的 input size 会让批量 sweep 失控。
这些是迁移解释；6.100L 没有提供实体仪器 lab，默认只处理合成或公开文件，不连接硬件。

## Spyder 是历史包装，文件、测试与语义才是交付边界

这些材料随 Fall 2022 课程发布，却复用了多个年份的文件：PS1 starter 与 6.100A 相同，
`put_in_function.py` 可追溯到 2017，PS0/PS5 包也含更早文件。现代环境可以替换编辑器，
但不能默默改题。

PS1 只编辑 `ps1a.py`、`ps1b.py`、`ps1c.py`；把它们与不可编辑的 `ps1_tester.py`、
`put_in_function.py` 放在同一目录，并保留转换脚本依赖的注释锚点与变量名。运行 tester
会生成 `ps1a_in_function.py`、`ps1b_in_function.py`、`ps1c_in_function.py`；这些是
中间文件，不是学生提交或兼容 patch。公开 tester 的 8 个用例只是正式 grader 的子集，
也不覆盖所有输入位置、输出格式、注释与风格要求。

PS5 安装的包名是 Pillow，代码通过 `PIL` namespace 导入。只补 `ps5.py` 中指定的
`pass`，保持 tester、`.obj` fixtures、输入图片与字体不变；`test_ps5_student.py` 只测
`extract_end_bits` 和两张隐藏图，不测 color-vision filter。跑完 student tester 后，
还要单独核查 filter 与原班人工评分的 3 张输出图片。若 package API、路径或图片格式
导致失败，保存原错误、最小复现、版本锁和兼容 patch；不要从未知镜像下载二进制包。
教材为 Guttag 第 3 版，Syllabus 指向 MIT Press 的纸书/电子书与代码勘误；OCW 的
lecture notes/code、finger solution、recitation 和 PS bundle 才是本文确认的公开材料。

一个合适的 **EEDIY 补充、不是 MIT 官方作业** 是“波形质量报告器”：从仓库读取一份合成
CSV 且不修改输入文件，检查 sample interval、空行、非数字与越界值，输出 min/max/mean、阈值 crossing 和
机器可读摘要；至少为 normal、boundary、invalid input 建测试，并保留一例故意 alias
buffer 的失败测试。提交 source、测试、样例、依赖锁、原始输出与一条重运行命令。课程没教
过的滤波器、FFT 或硬件采集不得作为默认要求。
