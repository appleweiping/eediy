### 旧作业与旧硬件账本

[官方 homework index](https://ptolemy.berkeley.edu/projects/chess/eecs149/homework/index.html)列出 7 次基于教材章节的作业，研究生另加 exercises，页面没有公开 answer key。适合的自学反馈不是立刻搜答案，而是先写模型假设与推导，第二天重新推一次，再用仿真、量纲、极限情形或 model checker 交叉核验；若两次结论不一致，就把差异写成待审问题，而不是默默改掉第一次记录。

[官方 labs/project 页面](https://ptolemy.berkeley.edu/projects/chess/eecs149/project.html)展示的是一套很具体的 2015 环境。Lab 1 用 Bluetooth WiiMote 校准 accelerometer；Lab 2 在 NI myRIO、Eclipse、Xilinx SDK、LabVIEW/MicroBlaze 上建链；Lab 3 做 bare-metal C、interrupt、tone 与 ADC；Lab 4–5 用 C state machine、CyberSim 和 Kobuki 做 hill-climb 的模拟与部署；Lab 6 转向 Statecharts/LabVIEW；Lab 7 是项目管理，随后 3–4 人完成 final team project、live demo、presentation、report 和短视频。实验评分内部又分 prelab 10、checkout 45、report 45。旧硬件、专有软件和 staff checkout 缺一项，都不能把移植版称为原 lab 完成。

## 迁移时保留模型，替换设备

1. 对一个一阶 plant，从连续方程推到离散更新式，分别写出 sample time 与 task period，并解释两者不相等时哪条近似先失效。
2. 把两状态 controller 画成 state machine，为它写一个 invariant 和一个 temporal property，再给出会破坏其中一条性质的输入序列。
3. 说明 interrupt 与主循环共享状态为何会产生 race，并对一组 periodic tasks 做一次 rate-monotonic schedulability 检查。

若第 1 题过不了，先补 differential equations、sampling 和 signals and systems；若第 2 题只能画流程图却写不出性质，先补 automata 与 logic；若第 3 题只会加 mutex 而算不出 deadline，先补 concurrency 与 real-time scheduling。通过后按“continuous dynamics 与 sensing → discrete/modal/hybrid models → composition 与 formal properties → execution time 与 scheduling → concurrency、network、security”阅读 version 2.3。每一块都交一份模型、一份推导、一个可运行反例和一次修正记录，进度以证据闭环为准，不必硬套 2015 的周数。

### 有机器人和没有机器人是两条证据链

[Lingua Franca embedded labs](https://www.lf-lang.org/embedded-lab/)来自多代 EECS 149 教学经验，用 C、Lingua Franca coordination 与 RP2040，在 Pololu 3pi+ 2040 robot 上练习反应式和实时控制。它是现代替代路线，不是 Fall 2015 的正式 graded labs；完整复现仍需要指定机器人。没有硬件时，应保留同一调度、传感器和执行器接口，改用 deterministic simulation，并在报告中写明没有验证 Bluetooth、ADC、motor driver、机械摩擦或电池行为。

旧 Lab 1–7 的物理复现只应在低压、限流、有急停且有人监督的实验环境进行。不要把 Kobuki 或 3pi+ 放入公共通道，不要把控制器接到车辆、医疗设备、电网或其他会造成人身和财产风险的对象。公开条件下可认定的完成证据包括：教材章节注释、7 次作业的盲做稿与复核、状态机和时序模型、调度测试、模拟 trace、故障注入记录。依据官方 archive 的资源表，不可认定的部分包括 2015 同期录像、bCourses/Piazza、官方 answers、2015 两场 midterm solutions、专有 toolchain、实体 checkout 与团队评分。

## 若目标只是 POSIX 实时服务，改走 CU Boulder

[CU Boulder 的 Coursera 课程](https://www.coursera.org/learn/real-time-embedded-systems-concepts-practices)更集中于 rate-monotonic scheduling、POSIX threads、Embedded Linux 和 Raspberry Pi 3B+，编为 4 modules 与 11 assignments；视频、作业或证书的完整访问可能取决于付费证书、free trial 或平台当时的 full-course 选项。要研究 hybrid model、temporal logic、refinement 与 model checking，优先 Berkeley；要尽快动手做 POSIX/RT service 和 Linux timing，且能取得支持的 Raspberry Pi，再选 CU Boulder。后者不能替代前者对 CPS 语义的训练。

### EEDIY 只补一个仿真结课件

EEDIY 建议的结课项目是“离散事件调度器加一阶 hybrid plant”，明确不是 Berkeley 官方 final project。仅在仿真中实现 rate-monotonic 与 EDF，注入 jitter、missed deadline、sensor dropout 和 mode switch；一边用 response-time analysis 给出解析预期，一边从 event log 重建 deadline miss 与 safety invariant。交付内容包括模型假设、调度器与 plant 源码、固定 seed、事件原始记录、性质检查、解析/仿真偏差和失败案例。只有当第三方能用一个命令重跑全部场景、故意破坏优先级后能触发检查、修复后回归通过，才算得到一件比“机器人动起来了”更可靠的 CPS 作品。
