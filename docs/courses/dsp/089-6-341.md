## 先拿背景考试给自己判一次卷

MIT 6.341 是 Alan Oppenheim 在 Fall 2005 开设的研究生课程，不是离散时间信号与系统的
第一门课。[Syllabus](https://ocw.mit.edu/courses/6-341-discrete-time-signal-processing-fall-2005/pages/syllabus/)
假定学习者已经能熟练处理 LTI 系统、采样、Fourier transform，以及确定性和随机信号的
bilateral z-transform；当年的直接先修是 6.011。课程把第一次背景考试设为不计入总评
的诊断，并明确把 80% 以下视为基础薄弱的信号。

独立学习时，我会先在不看答案、不给自己延时的条件下做 Fall 2005 background exam，
把 80% 当作“先安排一次集中复习”的触发线，而不是退课线或能力判决。官方原文只说低于
80% 提示背景可能明显薄弱。分数之外还要检查三件事：能否由 pole-zero 图解释
minimum phase 与 group delay，能否在时域和频域同时说明 downsampling 何时 alias，
能否把随机过程的相关函数接到功率谱。如果只能调用 `fft`、`filter`，却说不清归一化
频率、ROC 或相位，那么先回到 Signals and Systems，比从第 1 讲硬冲更省时间。

## 这套公开材料哪里完整，哪里并不完整

[Lecture Notes](https://ocw.mit.edu/courses/6-341-discrete-time-signal-processing-fall-2005/pages/lecture-notes/)
列出 23 个 lecture 位置，其中第 2–13、15–22 讲有讲义；第 1 讲课程介绍、第 14 讲
guest lecture 和第 23 讲 Caruso’s Orchestra 没有对应讲义，OCW 也没有课堂视频。
讲义依次涉及 phase/group delay、minimum-phase/all-pass、采样率变换和 noise shaping，
IIR/FIR 结构与设计、polyphase、linear prediction，再到 DFT filtering、spectral
analysis、FFT、chirp transform、STFT 和 modulated filter bank。

课程使用 Oppenheim、Schafer、Buck 的 *Discrete-Time Signal Processing* 第 2 版，
题号和阅读都按该版编排；教材本身没有随 OCW 页面开放。也就是说，公开讲义适合定位
每一周的重点，却不能保证替代指定教材。购买旧教材和使用商业 MATLAB 都可能产生成本，
应在开学前决定；不要做到 Problem Set 4 才发现题目一直在引用手边没有的章节。

## 十一份题、两次项目、三套考试应当交错推进

[Assignments](https://ocw.mit.edu/courses/6-341-discrete-time-signal-processing-fall-2005/pages/assignments/)
公开 Problem Set 1–11 及全部解答；[Exams](https://ocw.mit.edu/courses/6-341-discrete-time-signal-processing-fall-2005/pages/exams/)
还给出 Fall 2005 与 Fall 2004 的 background、midterm、final 以及对应解答。更有效的
顺序不是先读完 23 讲再集中刷题，而是按原 calendar 的依赖推进：

1. 先做 PS1–PS3 与背景考试，巩固 phase、sampling 和 z-transform 基础；
2. 读到 filter structures/design 后做 PS4–PS7，同时启动 Project I；
3. Lecture 14 发出 PS8，Lecture 15 读 DFT；按原日程在 Lecture 15 后闭卷做 2005
   midterm，再用 Lectures 16–17 完成 PS8；
4. 从 Lecture 17 的 spectral-analysis 段开始 PS9，再接 PS10–PS11、Project II 和
   2005 final；2004 试卷留作第二次独立测量。

每份题都先留下完整推导和假设，再看官方解答做红笔差异记录。只把最终式改对还没有解释
为什么会错：要标出错误属于变换定义、稳定性/因果性、频率尺度、结构复杂度还是数值实现。
课程没有公开 recitation 和 office-hour 讨论，独立学习者只能用这份 error log 记录
哪些概念需要重做。

## Project I 与 Project II 分别要求什么

[Projects](https://ocw.mit.edu/courses/6-341-discrete-time-signal-processing-fall-2005/pages/projects/)
提供一份统一说明、Project I 的两个 `.mat` 文件，以及 Project II 的 52 个 `.wav`
文件。Project I.A 用 N=1 与 N=50 的 all-pass filter 检查“耳朵不在意相位”这一说法，
要求 impulse response、magnitude、group delay、pole-zero 图和听感解释。Project I.B
把 44.1 kHz 含噪语音交给 Butterworth、两类 Chebyshev、elliptic、
Parks–McClellan 与 Kaiser 设计，比较 order、每输入样本乘法数、稳定性、群延迟和去噪
结果。

Project II 沿用同一个去噪问题，直接增加 compressor-by-4 和每输入样本最多 17 次乘法的
“硬件”预算。报告必须分别算出直接实现与 polyphase 实现的 multiplication count，并用
指定语音的 waveform 和试听结果解释滤波代价。原作业要求三份书面报告：
Project I.A 最多 5 页，I.B 最多 10 页，Project II 最多 10 页；不提交 MATLAB code，
也没有正式项目解答。因此报告必须足以让读者看出选择依据，而不是让代码代替论证。

## Athena 消失以后，迁移也必须可核验

官方项目只支持 2005 年 MIT Athena 上的 MATLAB 工作流；OCW 明确不提供 Athena
访问。说明中的 `usound110.m`、`usound441.m`、`wavread` 和 Athena Sun 播放路径都带
有时代边界，当时连 Athena Linux 都不在项目支持范围。今天继续用 MATLAB 时也要检查
旧函数替代和 Signal Processing Toolbox；改用 GNU Octave 或 Python/SciPy 则是
EEDIY 迁移，不是 MIT 官方项目环境。

迁移时先记录输入文件名、采样率和原始变量名，再逐个建立旧 MATLAB 到新函数的对应表。
每个 IIR 设计都检查 pole 半径和 second-order-section 实现；每个 FIR 设计都核对线性相位、延迟
和频率归一化；decimation 前验证阻带，再核对输出确为 11.025 kHz。浮点容差、窗函数
默认值和 dB 定义必须写入报告。若 Octave/Python 与旧 MATLAB 得出不同 order，不能挑
看起来最好的结果交差，而应保留版本、参数和差异解释。

## 结课目录要能复算三份项目报告

按官方 [Projects](https://ocw.mit.edu/courses/6-341-discrete-time-signal-processing-fall-2005/pages/projects/)
的报告边界，结课目录应包含 PS1–PS11 的独立解答与勘误记录、背景诊断与两套计时考试、
三个项目报告和迁移后的代码。Project I.A 报告要保留 N=1/N=50 的 pole-zero、magnitude
与 group-delay 对照和听感；I.B 要逐种列出滤波规格、order、coefficients 或 SOS、
稳定性与 waveform；Project II 要把 decimation filter 的阻带、polyphase 运算式和
17-multiply 预算放在同一页核对。试听时控制音量，避免用未经限幅的输出直接驱动耳机。

Python/Octave 只替换已经消失的执行环境，不能删掉 Project I 的相位比较、Project II
的运算次数限制或三份报告的页数边界。若 Project II 只留下“听起来更干净”的音频，却
算不清每个输入样本的乘法次数，就没有完成原项目要求。
